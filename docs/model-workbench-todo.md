# 模型训推未来待办

本文记录模型训练、管理、评估、部署、调用五个页面尚未完成的真实业务能力，供后续前后端实施和验收使用。现阶段是前端原型：默认 `VITE_USE_MOCK=true`，演示操作保存在浏览器会话的 Pinia 状态中，刷新后恢复示例数据。页面显示“已部署”“运行中”或模拟检查成功，不构成真实训练、部署或外部接口连通的证据。已有页面行为和请求字段见 [模型训推页面组件与接口说明](model-workbench.md)。

## 当前已预留的前端入口

下表表示前端已经写好请求调用或请求封装，**不表示仓库内已有对应后端、数据库或模型服务**。其中新增契约仍需与后端确认。

| 前端请求 | 用途 | 当前缺口 |
| --- | --- | --- |
| `GET /api/v1/model-workbenches/current` | 读取五页所需的模型、任务、服务、调用、评估和数据集快照 | 后端聚合查询及持久化 |
| `POST /api/v1/models` | 注册模型资产和初始版本元数据 | 资产与版本落库、产物关联、外部模型标识 |
| `POST /api/v1/training-tasks` | 登记训练任务 | 训练执行、调度、进度、日志与产物发布 |
| `POST /api/v1/model-services` | 登记模型版本与服务地址的绑定 | 凭据关联、服务接入及真实部署动作 |
| `POST /api/v1/model-services/{id}/check` | 请求后端检查服务 | 受控连通性及鉴权检查、状态回写 |
| `POST /api/v1/tasks/execute` | 发起模型治理调用、知识编辑和评估任务 | 后端任务执行器、供应商适配、异步结果及审计 |
| `GET /api/v1/metrics` | 读取正式评估指标编码 | 指标配置及评估结果关联 |

浏览器请求中的 `Authorization: Bearer accessToken` 是平台用户令牌，不能用作 DeepSeek 等供应商的 API Key。当前“模型接入配置”页面仍是展示占位。

## 待办清单

### P0：打通真实接入的基础能力

- [ ] **确定数据模型并持久化。** 建立模型资产、模型版本、训练任务、数据集版本、服务、凭据引用、调用记录、评估结果和操作日志。每条记录使用稳定 ID；前端刷新后从后端恢复，不再依赖会话内模拟状态。完成标准：五页读取同一批持久化对象，任务、服务和版本之间的引用可追溯。
- [ ] **实现现有前端请求契约。** 对齐上表的路径、字段、状态和统一响应体；明确分页、错误码、权限和幂等规则。`GET /model-workbenches/current` 必须返回完整且一致的当前范围快照，不能把分页局部数据当作全量统计。完成标准：`VITE_USE_MOCK=false` 时五页正常读取，后端失败会明确报错。
- [ ] **建设供应商凭据管理。** 在后端安全保存和轮换 API Key，仅向前端返回凭据编号、供应商、脱敏名称和校验状态；服务记录关联 `credential_ref`。建议新增凭据创建、列表、更新、测试和停用接口，具体路径与权限由后端设计确认。完成标准：浏览器请求、URL、页面状态和普通日志中均不出现供应商密钥；平台用户令牌与供应商密钥分开使用。
- [ ] **实现外部模型适配器。** 为 DeepSeek 等供应商保存 `provider`、`base_url`、实际模型 ID、接口协议、凭据引用和超时配置；由后端完成鉴权、请求转换、错误映射和响应解析。完成标准：能通过已登记服务完成一条真实调用，并在记录中看到实际绑定的模型版本和服务。
- [ ] **实现受控连接检查与准确状态。** 后端校验服务地址的协议、目标主机和访问范围，使用服务关联凭据执行轻量检查，记录时间、耗时、结果及错误原因；阻止访问内网敏感地址等不允许的目标。前端“已登记”“检查通过”“运行中”“离线”应各有明确含义。完成标准：无效地址、缺失或错误密钥均不能被标记为运行中；检查失败时展示原因。
- [ ] **接通真实模型调用与审计。** `model_risk_governance` 根据 `service_id` 和绑定版本选择后端适配器，返回原始输出、治理后输出、风险判定及可选链路编号。后端校验服务、模型、版本一致性，并执行敏感输入和输出的脱敏、留存期限及访问控制。完成标准：调用记录可从后端重新读取；失败调用不显示成功结果。

### P1：实现训练、产物与版本闭环

- [ ] **定义本地模型资产。** 模型管理区分完整权重、LoRA/QLoRA Adapter 和外部供应商模型；记录基础模型版本、产物存储地址、配置/Tokenizer 地址、校验值及适用运行环境。完成标准：能从版本记录定位到可加载的实际产物；仅保存训练参数不能被标记为已训练版本。
- [ ] **实现训练执行器。** 将训练任务登记与实际启动分开，增加启动、取消、失败重试、状态查询及异步进度和日志能力；训练器从已授权的数据集版本读取数据，保存检查点。建议补充相应训练任务操作与日志接口，路径待确认。完成标准：新建任务先为待启动，真实执行后才出现进度、损失曲线与检查点；失败原因可查询。
- [ ] **发布和管理模型版本。** 训练成功后校验产物并发布独立版本，保留基础版本与数据集版本的关联；提供版本列表、详情、发布、停用和回滚能力。对 LoRA 记录基础权重与 Adapter 的组合关系；对外部模型记录供应商返回的真实模型 ID。完成标准：版本号映射到明确、不可混淆的产物或供应商模型 ID，服务可绑定指定版本，历史版本不会被覆盖。
- [ ] **按供应商能力支持外部微调。** 仅在供应商开放微调接口时，后端提供数据准备、任务提交、状态查询和结果模型登记；若只开放推理接口，则训练页应禁止将该模型作为可训练基础模型，并说明可使用的替代方式（提示词、检索增强或输入输出治理）。完成标准：页面不会把普通推理 URL 当作训练接口。
- [ ] **接通数据资源中的真实数据集版本。** 训练和评估选择器从数据资源服务读取有权限使用、已就绪的数据集及固定版本；保存数据集 ID、版本、校验信息和使用记录。完成标准：训练任务引用的数据集可复查，数据更新不悄悄改变历史任务输入。

### P2：评估、部署运维与交付验收

- [ ] **实现真实版本评估。** 评估任务绑定同一模型的基线版本、编辑后版本、固定测试集版本及正式指标；异步运行并保存分母、分子、样例和报告。知识编辑任务完成后，不自动假定已经产生新版本或评估分数。完成标准：任意展示的分数都能追溯到任务、指标、模型版本和测试集版本。
- [ ] **实现本地部署生命周期。** 对本地模型补充部署创建、启动、停止、重启、健康检查、日志及版本切换；明确执行环境、资源配额和失败回滚。外部 API 使用“接入/绑定”流程，不宣称平台在供应商侧部署了模型。接口路径及基础设施方案待后端确认。完成标准：本地服务状态由真实运行实例和健康检查决定。
- [ ] **完善调用与服务可观测性。** 记录请求编号、版本、供应商或实例、耗时、状态和错误类别，提供调用历史查询、服务健康趋势及必要的告警；敏感文本按权限与脱敏策略展示。完成标准：页面统计来自持久化记录，异常可定位到一次具体调用或服务检查。
- [ ] **完成端到端联调。** 分别验证本地模型和外部 API 两条链路，覆盖注册、凭据配置、检查、调用、训练、产物发布、评估和版本切换；同时验证密钥错误、服务不可达、训练失败及后端超时。完成标准：关闭 Mock 后不回退演示结果，所有成功状态都由后端真实返回。

## 实施顺序与界面用语

建议先完成 P0 的数据、凭据和供应商调用链，再完成 P1 的真实训练与版本管理，最后接入 P2 的评估和部署运维。开发期间，前端应将“登记服务”后的状态准确表述为“已登记、未检查”；只有后端检查通过且可调用时才显示“运行中”。对外部接口，“部署”页实际承担的是接入与绑定职责。

本清单是后续实施范围，未勾选项目均不得从当前页面表现推断为已经完成。
