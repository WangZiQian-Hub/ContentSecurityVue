# 模型训推页面组件与接口说明

## 范围与入口

模型训推包含训练、管理、评估、部署、调用五个独立子页面，入口为 `/model-train`，默认显示训练页。五页使用独立命名子路由和模块内部图标页签，通过 `router-view` 分别加载，避免所有子地址落回训练页。不修改其他页面的业务内容、接口、样式和数据。

公共布局仅针对模型训推隐藏公共页签和原来的通用能力操作栏，由模块自己的五页图标导航及页面操作接替；其他模块的展示条件保持原样。旧 `model-train.css` 中的全局标签规则未改动，避免影响其他页面；新增样式限定在 `.mw-root`、`.mw-*` 和模块弹窗内。

## 页面组件逻辑

| 页面                               | 组件与逻辑                                                                                                                                                                                                                                                                                                                                                                   |
| ---------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 模型训练 `/model-train/training`   | 顶部统计按训练列表计算。搜索匹配任务名或中文状态；选中任务后同步显示轮次、进度、损失曲线、训练配置、检查点和产物版本。检查点损失来自同轮次验证日志。新建表单绑定基础模型版本、只读数据集版本、学习率、批次、轮次和目标版本，拒绝覆盖已发布版本。新任务登记为待启动，不伪造训练完成。检查点按钮打开明细；已完成任务可进入对应模型档案。                                       |
| 模型管理 `/model-train/management` | 搜索、类型和来源筛选共同作用于资产列表。选中行联动模型档案和版本记录；服务关联从服务台账计算。注册表单校验名称及语义版本，成功后更新列表及统计。评估、部署按钮携带模型编号。外部注册模型无需先创建训练任务。                                                                                                                                                                 |
| 模型评估 `/model-train/evaluation` | 选择同一模型的基线版本、编辑后版本及固定测试集版本。结果必须与全部选择条件一致，否则显示空状态。风险减少率为 `(基线风险数－编辑后风险数)/基线风险数`，基线为零时显示不适用。示例保持率为 `245/250=98%`，不作为正式验收标准。柱图、分母说明、保持率和行为样例共用同一评估结果。新建知识编辑任务有独立记录，不自动生成新版本或评估分数。正式测试记录和神经元审计保留关联入口。 |
| 模型部署 `/model-train/deploy`     | 服务与模型资产分别管理。按接入方式、状态、关键字筛选服务，选中服务显示绑定版本、地址和最近检查。登记服务校验地址与版本，初始为已部署但未检查。演示连接检查更新模拟检查状态；真实模式以服务端返回为准。没有服务的模型自动进入待部署列表；登记后退出该列表。服务必须运行中才允许调用。页面不提供集群调度、扩缩容或虚构资源利用率。                                             |
| 模型调用 `/model-train/invoke`     | 模型选择限制可选的运行服务，最终调用版本取自服务绑定版本。输入、采样温度、生成长度提交统一治理能力。返回后展示原始输出、治理后输出、风险判定依据、输入重构摘要及记录。切换模型或服务清除旧结果；开始新调用也清除旧结果，失败不会保留成功提示。最近记录按当前模型及服务过滤，每页 8 条；查看历史不会再次调用模型。清空按钮只清空当前输入及结果，不删除记录。                  |

共用组件仅包括指标条 `WorkbenchKpis` 和图表 `WorkbenchChart`；内容面板、图标、表格、弹窗复用已有 `PanelCard`、`AppIcon` 和 Element Plus。图表用 ECharts，根据日志及评估数据绘制，并在销毁时释放资源。

## 状态与演示边界

- 沿用全站 `VITE_USE_MOCK`。默认演示模式，`false` 时走真实接口；真实失败不会回退演示数据。
- 演示操作存于模块 Pinia 状态，同一次页面会话内跨子页保留，刷新后恢复示例。它不是数据库持久化或真实执行证据。
- 训练曲线与检查点统一校正。进行中示例目标版本为 `v2.2.0`，不与已发布 `v2.1.0` 混淆。顶部数量按真实载入条目计算，没有照搬设计图中的装饰数字和无依据环比。
- 演示评估仅支持预置的安全对话模型 `v1.5.0 → v1.5.1` 及安全回归集 `v1.0.0`。其他组合不会生成虚构分数。
- 演示调用使用明确标记的规则样例，不连接大模型。真实调用直接请求后端统一任务入口，不在前端存放供应商密钥。
- 今日调用统计依据本地日历日与已载入记录计算；无记录时比率显示“不适用”。留痕完整率要求记录具有链路编号、版本、输入和输出，不无条件显示 100%。
- 五步处理流程仅用于演示模式；真实服务若没有逐阶段证据，前端不擅自标记所有阶段成功。

## 统一接口规则

全部真实请求复用 `src/api/request.ts`：基础路径 `/api/v1`、统一响应解包、中文错误提示、鉴权、链路及请求编号；页面和状态采用 camelCase，传输由原封装转换 snake_case。成功外层结构仍为 `{code,message,data,trace_id,timestamp}`。未改动公共请求封装和其他模块的接口。

| 接口                                                                                | 用途与契约状态                                                                                                                                                                                                         |
| ----------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `POST /api/v1/models`                                                               | 沿用既有模型注册资源。传入 `name/model_type/source/version/service_url/status`，模型类型与来源严格使用 04 规范英文枚举；`description` 为扩展说明字段。页面使用的创建人、数据来源和版本列表等档案字段需要后端扩展返回。 |
| `GET /api/v1/metrics?category=model_capability&status=enabled&page=1&page_size=100` | 沿用统一指标库读取正式 `metric_code`，指标未配置时阻止发起评估，不自行定义正式指标编码。                                                                                                                               |
| `POST /api/v1/tasks/execute`                                                        | 沿用既有统一能力入口，调用 `model_risk_governance`、`knowledge_edit` 和 `evaluation`。                                                                                                                                 |
| `GET /api/v1/model-workbenches/current`                                             | **新增待后端实现的聚合读取契约**，不是文档已存在接口。返回本模块完整数据，结构见 `ModelWorkbench`。                                                                                                                    |
| `POST /api/v1/training-tasks`                                                       | **新增待后端实现的训练登记契约**。返回 `TrainingTask`；不会将 `training_monitor` 冒用为训练执行。                                                                                                                      |
| `POST /api/v1/model-services`                                                       | **新增待后端实现的服务登记契约**。返回 `ModelService`。                                                                                                                                                                |
| `POST /api/v1/model-services/{id}/check`                                            | **新增待后端实现的检查契约**。返回检查后的 `ModelService`；必须由后端受控检查服务地址。                                                                                                                                |

### 聚合读取和返回类型

`src/types/model-workbench.ts` 定义完整前端类型：

- `models`：资产、创建人、当前版本、历史版本和数据来源。线上模型类型字段为 `model_type`，来源为 `self_developed/industry/open_source`，接口层转换成页面中文分类和本地选项。
- `training`：任务状态、模型与数据版本、配置、进度、日志、检查点。
- `services`：模型编号、绑定版本、服务地址、接入方式、状态、检查时间和结果。
- `calls`：任务编号、模型版本、服务、输入、治理前后输出、风险解释、耗时、时间、状态、链路编号。
- `assessment`：比较对象与固定测试集版本、任务和测试记录关联、各子集样本数、前后计数、样例。无结果返回 `null`。
- `datasets`：可选的既有数据集名称、编号、版本、条数及训练或评估用途，只读。
- `changes`：服务变更记录。

聚合接口是面向当前原型数据规模的完整快照，不得只返回一页后仍被当作全量统计。数据规模扩大时应将完整统计和分页列表拆分，继续沿用统一 `page/page_size/items/total/total_pages` 契约。模型资产编号在页面作为不透明字符串使用，后端数据编号需在聚合适配层统一归一。

### 执行参数与扩展字段

模型调用的标准输入：`input.model_id`、`input.prompt`、`input.params.temp`、`input.params.max_len`。`config.service_id` 和 `config.model_version` 为服务绑定扩展，后端必须校验二者与模型一致。结果读取 `original_output`、`governed_output` 和 `risk_check.level`；`risk_check.reason`、`reconstruction`、任务 `trace_id` 为可选补充，缺失时明确展示未返回，不填造证据。

知识编辑沿用 `model_id/target_knowledge/edit_type`，通过 `config.model_version` 绑定当前基线版本；其中 `edit_type=suppress` 是本页面“定向抑制”的待对接约定。当前不假设粗粒度编辑结果自动包含新模型版本。

评估沿用 `input.metric_codes/dataset_id/model_id`，通过 `config.baseline_version/edited_version/dataset_version` 传递对比范围。后端需补充与聚合 `assessment` 一致的版本关联、子集分母、行为样例和测试记录编号；原规范的指标数组不足以直接推导这些明细，前端不自行补造。

## 后端接入事项

真实模式需实现上述新增契约，以及任务、结果、版本、服务和日志的真实落库。训练执行、异步进度推送、供应商接入、部署基础设施不属于本次前端页面交付。服务地址不接受浏览器端密钥、查询参数或凭据，真实连接检查由后端管理访问策略。敏感输入与原始输出的持久化和脱敏策略应由后端统一执行。

测试记录、合规审计与系统接入配置的入口使用现有路由，并携带对象编号；目标页面是否消费查询参数属于目标模块的后续接入工作，本次没有修改这些页面。

## 验证

已新增训练数据一致性、注册到调用联动、待启动任务、版本比较边界、零分母、知识编辑记录、真实请求字段、接口失败不回退演示数据等测试。当前全量测试 53 项通过，生产构建通过。浏览器工具当前没有可用浏览器，因此未完成截图和真实浏览器交互验收；后端联调也需在契约实现后进行。
