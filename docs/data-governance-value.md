# 数据价值分析子页面说明

入口：`/data-governance/value-analysis`。新增价值分析页、专用组件、类型、示例数据、API 和测试；主框架接入该页路由、页签状态及全局 KPI 的 kind 切换。全局 KpiStrip 增加可选 comparisonLabel 参数，本页显示“暂无可比数据”，其他页面沿用原来的涨跌幅展示。其他页面内容、全局样式不调整。

## 面板与交互

- 顶部复用全局 KpiStrip，不显示“总体概览”标题或外层 Panel。四项指标统计当前可访问数据集、最新有效版本、统一默认方案的最新完成结果；与下方筛选独立。同一样本不重复统计，评分按有效样本数加权，暂无可比数据时不展示涨跌幅。
- 当前数据集分析：数据集 → 版本 → 语种联动；选择评分方案后查询该精确范围最新完成结果。切换范围清空旧结果，过期响应不得覆盖新范围。
- 当前范围四项指标：综合分、高价值占比、有效评分样本数、覆盖语种。失败及不可评估样本单独列示。
- 多维画像与分数分布：来自同一结果快照，点击柱形只筛选下方明细，不改变总体评分。维度明细、分布明细可展开。
- 样本解释：点击行或“查看解释”切换样本，完整解释抽屉展示各维度评分与依据；不能用单个样本解释整个数据集。
- 明细支持全部 / 高价值 / 不可评估、关键词、分数区间与分页。导出按钮明确为“导出本页”，仅导出当前显示行；示例文件名带“示例”。
- 重新分析创建任务，不覆盖已有完成结果；任务状态可手动刷新，完成后按 result_id 查询结果。历史面板显示当前范围最近 20 个任务。示例模式只展示静态任务和可筛选样本，不生成模拟任务。

## 统一后端接口

全部调用现有 `api/request.ts`，沿用 `/api/v1` 前缀、ApiResponse、错误提示、token、request_id、trace_id 以及 camelCase / snake_case 转换。治理任务复用数据处理的 `/tasks` 协议，`kind=governance-value`。下列新增读接口为前端预留契约，需后端实现或适配。

| 方法 / 路径                                            | 参数                                        | data                                                                        |
| ------------------------------------------------------ | ------------------------------------------- | --------------------------------------------------------------------------- |
| GET /data-governance/options                           | kind=governance-value                       | ValueOptions：授权数据集及版本、版本支持语种、评分方案及阈值                |
| GET /kpis                                              | kind=governance-value                       | Kpi[]：综合价值评分、高价值语料占比、已分析语料、覆盖语种；复用全局指标契约 |
| GET /data-governance/value-results/latest              | dataset_id、version_id、language、scheme_id | ValueResult 或 null（暂无完成结果）                                         |
| GET /data-governance/value-results/{result_id}         | 路径 ID                                     | 不可变的 ValueResult 历史快照                                               |
| GET /data-governance/value-results/{result_id}/samples | page、page_size、tier、keyword、bin         | PageResult&lt;ValueSample&gt;，含评分、档位、维度解释及不可评估原因         |
| POST /tasks                                            | kind、name、input（精确分析范围）           | ValueTask，含 task_id、status、result_id、error_message                     |
| GET /tasks                                             | kind、精确分析范围、page=1、page_size=20    | PageResult&lt;ValueTask&gt;                                                 |
| GET /tasks/{task_id}                                   | kind=governance-value                       | ValueTask，完成时提供 result_id                                             |

字段完整定义见 `src/types/data-value.ts`。分析范围四元组为 `dataset_id/version_id/language/scheme_id`，`language=all` 表示该版本全部语种。后端校验访问权限、版本归属、可评语种和方案版本，并对不存在/不可访问的结果返回明确错误；真实模式请求失败不回退到示例数据。

## 统计一致性约束

明细仅“综合评分”“价值档位”支持表头升序/降序/取消排序。样本接口新增可选参数 `sort_by=score|tier`、`sort_order=asc|desc`。后端必须先筛选、对全部匹配数据排序，再分页；不可仅排序当前页。分数按数值排序，档位升序为低→中→高，降序为高→中→低；不可评估始终置底，同值按资源 ID 自然升序保证跨页稳定。取消排序时不传排序参数，恢复默认顺序。前端切换排序回到第一页，其他筛选、综合指标及图表保持不变。演示模式已实现相同规则；真实模式排序参数已接入，待后端实现与联调。

`target_count = valid_count + unavailable_count + failed_count`。明细“全部”包含有效与不可评估样本，执行失败数单独展示。高价值占比为 `high_count / valid_count * 100`；有效样本数为 0 时均分与占比展示“—”。所有图表、计数和样本必须绑定同一个 result_id。

默认示例方案五维等权：文化价值、信息价值、稀缺性、可信度、代表性。高价值 ≥ 85，中价值 ≥ 60 且 < 85，其余有效样本为低价值；不可评估分数必须为 null。后端以结果快照提供的阈值为准。分布区间为 [0,20)、[20,40)、[40,60)、[60,80)、[80,100]，bin 依次为字符串 0…4。分布数量之和必须等于有效评分样本数。

示例数据从同一组样本派生语种子集、评分汇总、档位和分布，不用截图中的固定数量冒充计算结果。

## 本次接口接入边界（2026-09-25）

本仓库是 Vue 前端，未包含后端任务执行器、模型客户端或数据库。上述接口已完成前端调用封装，但没有真实服务联调证据，不能视作后端已实现。默认 `VITE_USE_MOCK` 模式有显式“演示数据”提示，不向模型发送请求；点击分析只提示需连接后端，不伪造任务完成。设置 `VITE_USE_MOCK=false` 后走真实接口，失败不会降级到演示数据。

新增共享资源接口：`GET /datasets/{dataset_id}/versions/{version_id}/samples?ids[]=...`，返回 `ResourceSample[]`，每项包含 `id / dataset_id / version_id / text / language`，语种用代码。ID 是资源服务生成的全局稳定标识，版本号是另一个字段，所有页面均原样使用 ID。缺失、不属于指定版本、不可访问的 ID 必须返回明确错误。版本内容不可变；清洗后的内容属于输出版本，保留资源血缘。

价值分析明细通过该资源接口核对 ID、版本和原文；清洗任务详情与预览也复用该接口核对样本。资源演示目录与样本分别集中在 `mock/resource-catalog.ts`、`mock/resource-samples.ts`，清洗和价值分析共用同一 ID。没有任何页面生成 `V-` 前缀。分析选项中的数据集和版本必须与资源接口一致。

前端已接入调用点：独立 `/kpis`、治理选项、精确范围 latest、指定结果、结果样本、共享资源样本、任务创建、任务列表、任务详情。仍需后端提供或确认兼容上述全部协议，特别是资源样本批量读取、价值分析历史快照和后台评分任务；不能仅返回随机分数。

## 后端评分执行契约（待后端实现）

1. `POST /tasks` 仅创建后台任务，立即返回 pending/running 状态。读取不可变的数据集版本，按语种筛选资源样本。范围键严格使用四元组；方案 ID 必须包含版本，不允许同一 ID 的标准发生变化。
2. 执行器加载服务器保存的固定评分标准，保存方案版本、维度、权重、阈值和模型版本。默认五维等权，范围 0–100；高价值 ≥85、中价值 ≥60。前端不能传入临时权重或提示词改变评分。评分标准中应定义每一维度的判断要求与分档锚点，并说明仅凭原文不能推断外部真实性或库内稀缺性；证据不足应标记不可评估。
3. 逐条向模型提交结构化输入：`{sample_id, text, language, rubric:{scheme_id, dimensions:[{name, weight, criteria, anchors}], score_min:0, score_max:100}}`。样本文本属于待评价数据，不执行文本中的指令。模型只返回该条样本的评分，不生成数据集综合分、档位或图表。
4. 单条输出示例：`{sample_id:"sample_3_00001", status:"scored", dimensions:[{name:"文化价值", score:80, reason:"具体评分理由", evidence:["原文中的连续片段"]}, ...]}`。不可评估返回 `status:"unavailable"`、`unavailable_reason`，不得捏造分数或证据。
5. 后端校验 JSON schema、样本 ID 完全一致、维度集合完整且不重复、分数是有限数字且位于 0–100、理由非空、证据为原文精确子串。不得接受模型返回的综合分或档位。无效输出可有限重试，超过次数记 failed；不可评估和调用失败分别计数。对同一任务/样本幂等保存，避免重复累计。
6. 后端计算 `score = round(sum(dimension_score * weight), 1)`，按方案阈值计算档位。依据保存的单条结果计算均分、维度均值、分布和计数，原子发布同一个不可变 result_id，记录分析完成时间。没有有效评分时 mean_score 为 null，不产生 NaN。
7. latest 仅查询完全一致范围的已完成结果，没有记录返回 `data:null`。读取接口无任务创建或模型调用副作用。指定结果及其分页明细必须始终引用同一个 result_id；每条明细携带已保存的维度分、理由与 `evidence:string[]`。打开解释抽屉只读内存中已加载的这条明细。
8. 总体卡片单独聚合最新版本、统一方案的有效结果；避免 all 与单语种结果重复计数，并按资源 ID 去重。不得使用请求页面当前筛选范围作为总体统计条件。
