# 智能体轨迹接入与校验 后端接口与数据细则

日期：2026年11月6日

## 1 范围与接口现状

本说明面向后续后端实现和前后端联调。当前只生成文档，不修改后端代码。前端实施只能修改 `ContentSecurityVue`。截图数字是演示场景，不作为生产固定值。

已从前端源码确认：平台使用 `/api/v1`，统一 `POST /tasks/execute` 和 `GET /tasks/{task_id}`，上传使用 `POST /files`；合规已有接口必须全部保留。新页面不能占用已有 `/compliance/traces/{id}`，该接口返回平台溯源对象，与本页运行日志的标准化事件不是同一个模型。

本文新增领域前缀为 `/compliance/agent-traces`。下列新增接口、两个新能力编码及任务结果扩展均是**待后端实现的目标契约**，不是对现有后端可用能力的声明。不要用已有 `reasoning_audit` 编码承载不兼容的批量解析输入。

## 2 统一协议

### 2.1 请求响应与鉴权

以下 URL 均省略 `/api/v1`。HTTP JSON 请求与响应采用 snake_case；前端共享请求层自动将业务对象变为 camelCase。不要再在本模块对对象做第二次转换。

```json
{
  "code": 0,
  "message": "ok",
  "data": {},
  "trace_id": "request-trace-id",
  "timestamp": "2026-11-06T14:53:42+08:00"
}
```

`code=0` 表示成功。非零业务码沿用平台错误码注册方式，不在前端私自分配。失败响应使用合适 HTTP 状态、中文 message、同样的 envelope；data 可包含可展示的字段错误和重试提示。不要 HTTP 200 包装所有鉴权错误。HTTP 204 不适用于需要共享 request 解包的接口。

认证沿用 `Authorization: Bearer ...`。请求带 `X-Request-Id`；服务端 trace_id 位于 envelope，前端下一次请求可能携带 `X-Trace-Id`。**envelope.trace_id 是请求追踪号，data 内的 trace_id 才是业务轨迹 ID，两者不能混用。** 后端校验租户与对象权限；不能信任前端传入的 source_id、batch_id、artifact_id、文件名或原始位置来绕过授权。

所有写接口要求幂等：同一操作者、方法、路径、X-Request-Id 和相同规范化载荷返回同一业务结果；同一键不同载荷返回 409。真实网络重试复用原键，新的业务操作使用新键。幂等记录至少保留 24 小时，并在平台策略允许时延长；幂等命中也重新校验访问权限。

### 2.2 分页、时间与枚举

```json
{
  "items": [],
  "total": 0,
  "page": 1,
  "page_size": 20,
  "total_pages": 0
}
```

page 从 1 开始，page_size 默认 20、范围 1—100。非法页码返回 422；page=1 且空集返回上述空页；超过最后一页返回空 items、原 total 和 total_pages，前端据此恢复到有效页。样本排序固定为快照内 ingest_order、trace_id；不能按不稳定的默认数据库顺序分页。选择器列表也需要有界，不返回全部大批次原文。

时间用带时区 ISO 8601；耗时统一毫秒，Token 为非负整数。缺失使用 null 与 availability，不能用 0 代替缺失。真实零值有效。枚举使用稳定英文编码，中文标签仅供展示。

### 2.3 原始数据保真

共享 request 会递归改写 JSON 对象键。因此下列内容必须使用字符串传输：

- `raw_text`：原始日志或原始片段；不重新序列化以掩盖差异。
- `input_json`、`output_json`：工具参数、工具输出或任意用户 JSON 的序列化字符串。
- `source_path`、`record_path`、`target_path`：字段路径字符串。
- 格式示例的 `example_text`：完整可解析样例字符串。

标准 DTO 仍使用对象；只有任意载荷使用字符串。字符串值内的 tool_call_id、大小写键、用户参数不得转换。不要返回以 AUD-0042 或任意用户字段为对象键的动态字典；使用 `{id, value}` 数组。任何限制导致截断时返回 `truncated=true`、总长度及范围，不能返回损坏 JSON 却标注为完整原文。

## 3 领域对象与范围

| 对象 | 必要字段及规则 |
| --- | --- |
| 文件资产 | file_id、filename、size_bytes、sha256、owner、状态；不可变原始内容；同名不同文件不得混淆 |
| 来源 source | 本页 source_id 直接引用文件资产 file_id；来源选择器展示文件名；不等于格式编码；同一文件可关联多个批次 |
| 批次 | batch_id、display_id、name、batch_version、active_snapshot_id、created_at、allowed_actions；版本为整数 |
| 文件绑定 | batch_id、file_id、format_override、detected_format、解析状态、问题数、解析计数；批次内同一文件只绑定一次 |
| 解析快照 | snapshot_id、batch_id、batch_version_at_start、schema_version、adapter_versions、created_at；发布后不可变 |
| 轨迹样本 | trace_id、display_id、source_id、language、test_category、event_count、call_count、availability、snapshot_id |
| 事件 | event_id、event_type、ordinal、role、tool_name、call_id、source_ref、时间与用量来源；event_id 在快照中稳定 |
| 来源定位 | source_id、record_index、record_path、line_start、line_end、message_index、block_index、source_path；不适用项 null |
| 任务 | 平台 Task；task_id、capability_code、status、progress、result、error_message 等；不另建第二套状态 API |
| 导出产物 | artifact_id、task_id、batch_id、snapshot_id、kind、mime_type、filename、size_bytes、sha256、expires_at |

内部 ID 是稳定标识，展示编号另放 display_id；截图 AUD-2026-001、AUD-0042 可作为展示编号。若真实业务把它们直接作为唯一 ID，也应由服务端返回，不由前端拼接。Mock 内部 ID 使用 mock_ 前缀；复制业务标识时应明确复制内部 ID 还是展示编号。

批次汇总、校验与问题数是**整个 active snapshot** 的统计，不受来源下拉框、样本列表页码和当前样本影响。source_id 和 issue_type 只限制样本列表及预览。响应返回 scope 明确上述口径。切来源后，汇总 200 不应变成该文件的 100。

新文件绑定使 batch_version 增加，但不修改已发布快照。工作区将 staging 文件与当前快照结果区分；待解析文件不计入“已接入格式／成功轨迹”。解析成功发布新快照后统一切换汇总、列表与预览；失败保留上次成功快照并标注失败任务。

## 5 R01 上传原始文件

`POST /files`，multipart/form-data，字段 `file`。浏览器生成 boundary，不手填 Content-Type。沿用共享请求、认证与 envelope；最小响应为 `{"file_id":"file_001"}`。文件名、大小、哈希等可作为向后兼容的额外字段，不能破坏已有调用方。新增文件信息也可由 R04 查询资产后补齐，不强依赖旧上传接口返回新字段。

上传限制从 R02 的 upload_policy 获取：允许扩展名、最大单文件字节数、一次最多文件数；服务端执行同样校验，前端校验不替代后端校验。JSON 与 JSONL 是容器，不能仅按后缀认定 OpenAI 或 Anthropic 结构。文件上传成功不代表轨迹解析成功。

大文件应有明确上限。当前保留普通文件上传，不在本轮虚设断点续传；若后续需要分片上传，单独扩展平台文件服务。413、415 等返回清楚原因。未绑定资产按平台保留策略清理，不在页面上传失败时擅自删除其他业务资产。

## 6 R02 聚合工作区

查询参数：

| 参数 | 必填 | 说明 |
| --- | --- | --- |
| batch_id | 否 | 精确指定批次；不存在或无权限时不自动替换 |
| source_id | 否 | 来源文件 ID；与 batch_id 同时给出时必须有绑定关系 |
| snapshot_id | 否 | 已发布快照；未给出取该批次 active snapshot |
| trace_id | 否 | 恢复精确样本选择，需属于以上范围 |
| issue_type | 否 | time_missing、usage_missing、structure_invalid、call_unlinked 等 |
| q | 否 | 样本编号搜索，最多 100 字符，不解释为 SQL 或正则表达式 |
| page、page_size | 否 | 初始样本页，默认 1、20 |
| option_q、option_page、option_page_size | 否 | 来源选项搜索与分页，默认 1、50，最大 100 |
| batch_option_page、batch_option_page_size | 否 | 当前来源兼容的批次选项分页，默认 1、50，最大 100 |

首次无精确上下文时服务端选择当前用户可访问的最近批次，再选择其中首个文件和首个有效样本，并返回 resolved_selection 与 resolution=defaulted。若传入精确 ID 则只验证不偷换，非法组合返回 409 或 404。空批次返回 null 选择和空列表，不能借用别的批次。单独指定 source_id 时可为其选择最近兼容批次；URL 精确给出的 batch_id 必须保留或报错。

data 字段：

| 字段 | 必需内容 |
| --- | --- |
| resolution、resolved_selection | resolved／defaulted／empty；source_id、batch_id、snapshot_id、trace_id |
| formats[] | code、label、containers、availability、schema_version、description、example_text、mapping_version；支持、维护中、未适配必须可区分 |
| upload_policy | allowed_extensions、max_file_bytes、max_files_per_request |
| source_options | 分页摘要，item 含 source_id、filename、compatible_batch_count；名称来自服务端 |
| batch_options | 分页摘要，item 含 batch_id、display_id、name、active_snapshot_id、batch_version |
| batch | 批次基本信息、allowed_actions、staging_changed、active_snapshot_id |
| files | 本批次文件摘要 PageResult；每行见下文；默认 20，附 files_page/files_page_size 查询分页 |
| summary | 完整批次统计，见第 11 节 |
| validation | 结构、调用关联、时间、用量指标及可继续分析结论 |
| issues[] | 类型、严重性、受影响轨迹数、分析影响、最多 3 个示例定位对象 |
| sample_page | 与 R05 相同的分页摘要，便于首次渲染，不含原文 |
| selection_locator | 精确 trace_id 所在页码及稳定排序定位；指定 trace_id 时 sample_page 返回其所在页，或明确不在当前筛选内并返回冲突，不能无声跳到第一页 |
| scope | summary_scope=batch、preview_scope=source、snapshot_id、snapshot_created_at |
| export_options | 允许范围、允许内容、每种内容 availability 与 reason、脱敏规则、匿名化要求、支持格式 |
| active_tasks[] | 当前批次最近的非终态解析／导出任务摘要，便于刷新恢复，不返回无界任务历史 |

files 行包含：file_id、filename、size_bytes、detected_format、format_override、recognition_state、parse_status、parsed_trace_count、input_candidate_count、failed_record_count、error_examples、last_task_id、snapshot_id。recognition_state=recognized／ambiguous／unknown／pending；parse_status=pending／running／succeeded／partial／failed；原始候选数未知时 input_candidate_count=null，界面不能编造分母。error_examples 有 record_index、line_start、source_path、code、message，最多 3 项。

formats 是系统能力；本批次各格式已接入数量由 summary.by_format 给出。未接入的支持格式不计入 imported_format_count。接口内部使用聚合查询／批量读取，不为 20 个文件各调用一次远程统计。

## 7 R03 创建批次与 R04 文件绑定

### R03 创建批次

请求 `{"name":"轨迹审计批次"}`，name 长度 1—100，去除首尾空白。服务端生成 batch_id、display_id，返回完整批次基本对象，batch_version=1、active_snapshot_id=null。空批次校验各分母为 0，状态 not_applicable，不能显示 0/0 已通过。沿用幂等请求 ID，网络重试不创建多个批次。

### R04 批量绑定或更新格式覆盖

```json
{
  "expected_version": 1,
  "files": [
    {"file_id":"file_001","format_override":"auto"},
    {"file_id":"file_002","format_override":"langchain_trace"}
  ]
}
```

格式编码为 openai_messages、langchain_trace、anthropic_messages；auto 表示按结构识别。同批次已有文件采用 upsert 更新 format_override，不重复绑定；相同请求无实质变化不增加 batch_version。新绑定或覆盖改变时版本递增并标记 staging_changed。

对文件归属、存在性、大小、支持格式和 expected_version 全量校验，**整组原子成功或整组失败**；失败时不留下半组绑定。HTTP 409 返回 current_version；不能自动丢弃用户格式覆盖然后覆盖服务端最新数据。响应包含 batch、affected_files[]、staging_changed；可附初步识别结果，解析阶段仍要正式验证结构。

R04 不执行解析，不返回虚构的 100/100。解析中不允许改变本次任务捕获的文件集合或覆盖规则；返回 409 或将编辑明确保留为下一版本，不能让运行中输入漂移。本轮采用前者。删除已绑定文件不在本轮契约，不使用空数组当作删除全部文件。

## 8 R05 样本摘要列表

必要参数 snapshot_id；可选 source_id、issue_type、q、page、page_size。snapshot 必须属于路径 batch_id；不允许跨版本拼列表。返回 PageResult，item 至少含：

```json
{
  "trace_id":"trc_0042",
  "display_id":"AUD-0042",
  "source_id":"file_001",
  "filename":"openai_messages_demo.jsonl",
  "source_format":"openai_messages",
  "language":"en",
  "test_category":"prompt_injection",
  "event_count":18,
  "call_count":7,
  "issue_types":[],
  "availability":{"time":"available","usage":"available"}
}
```

列表不返回完整原文、全部参数、字段映射或所有事件。支持多个样本一次分页获取，禁止前端对列表每条再请求详情来凑下拉选项。语言 zh／en／other／unknown，未知不强分中英；类别为测试集标签，不能直接用作检出风险结论。

issue_type=time_missing、usage_missing 的返回集合需与 R02 的对应问题统计一致；当 issue 筛选用于批次全量定位时省略 source_id，返回条目中的 source_id 用于切换来源。

## 9 R06 聚合样本详情

必要查询 snapshot_id；可选 source_id、event_id、event_page、event_page_size、issue_type、q、event_types。event_types 是逗号分隔的事件类型白名单，例如 tool_call,tool_result，用于工具交互目录；省略则列出全部类型。event_page 从 1 开始，默认每页 50，最大 200。events.total 是过滤后的目录总数，event_count 始终是完整轨迹事件总数。source_id 给出时必须匹配样本，不匹配返回 409。sample 级 source_id、snapshot_id、trace_id 必须一并回显，便于前端核验。

原文片段默认不超过 64KiB；说明 kind=fragment／full 与截断状态。完整原文件按授权导出，不因本页预览绕开权限。若一行超过限制，返回安全截取范围和不可完整解析提示；不能把截断参数当作有效 JSON 再解析。

navigation 按与 R05 同样的 source_id、issue_type 和固定排序计算；到头尾返回 null。跨页返回邻居 page，前端不需拉取中间每条数据。为避免不适用的 q 改变导航，详情可接受同样 q 过滤并回显 navigation 的筛选上下文。raw source_ref 的行号是原文件位置，raw_preview.line_start 是片段展示的源行起点，两者需说明一致关系；record_index 从 1 开始，message_index／block_index／JSON 数组索引从 0 开始。

标准 DTO 的 event 字段是规范结构；mapping.target_path 用 `event.*` 作为事件逻辑路径。若 source_ref 是由系统生成的定位，不谎称源文件存在名为 source_ref 的字段，映射状态标 generated，并在 UI 显示“源文件与字段路径 → source_ref”。

## 10 R07 与 R08 统一任务

### 10.1 解析命令

```json
{
  "capability_code":"agent_trace_ingest",
  "name":"智能体轨迹解析",
  "input":{
    "batch_id":"batch_001",
    "expected_version":2,
    "file_ids":["file_001","file_002"],
    "mode":"parse_pending"
  }
}
```

file_ids 一次传一组，不为每条轨迹建任务。mode=parse_pending 只解析待处理或格式改变文件；retry_failed 仅重试失败记录；reparse_all 重新处理整个批次，显式确认后使用。所有模式最终生成**覆盖整个批次有效文件集合**的新快照，未变化数据可复用，但不重复计数。重复执行不把 200 累加成 400。

后端冻结输入、适配器版本和 batch_version，同批次只允许一个解析任务运行；竞争提交返回 409 并提供已有 task_id。前端不直接运行真实适配器。未知编码返回明确不支持错误，不降级为其他能力。

R07 成功返回平台 Task 对象，允许 HTTP 200 或 202，均带 JSON envelope。R08 返回同一任务字段。状态严格为 pending、running、succeeded、failed、cancelled；progress 为 0—100 的可选数，不返回字符串百分比。终态不可倒退。任务状态 succeeded 表示作业完成，记录级部分失败使用 result.outcome，不增加不兼容的 partial_success 任务状态。

解析 result：

```json
{
  "kind":"agent_trace_ingest",
  "outcome":"complete",
  "batch_id":"batch_001",
  "snapshot_id":"snap_001",
  "batch_version":2,
  "file_count":2,
  "parsed_trace_count":200,
  "failed_record_count":0,
  "unidentified_record_count":0,
  "schema_version":"1",
  "adapter_versions":[{"format_code":"openai_messages","version":"1"}]
}
```

outcome=complete／partial／empty；partial 代表作业完成并发布有成功数据的新快照，同时保留失败记录。empty 表示执行完成但没有有效样本，can_continue=false。全局崩溃或输入无法处理为 failed，不发布损坏快照。error_message 为可展示摘要，详细失败位置通过 R02 文件 error_examples 返回。首版不提供独立全量错误列表接口，若错误很多应允许导出错误清单，不能为每个错误新增 GET 路径。

### 10.2 导出命令

```json
{
  "capability_code":"agent_trace_export",
  "name":"智能体轨迹结果包导出",
  "input":{
    "batch_id":"batch_001",
    "snapshot_id":"snap_001",
    "export_kind":"package",
    "format":"zip",
    "scope":{
      "type":"batch",
      "source_id":null,
      "trace_ids":[],
      "issue_type":null,
      "q":null
    },
    "view":"ingest",
    "selected_trace_id":"trc_0042",
    "selected_event_id":"STEP-03",
    "contents":["normalized_json","offline_html","evidence_index","manifest"],
    "redaction_profile":"standard",
    "anonymize_ids":true,
    "locale":"zh-CN",
    "timezone":"Asia/Shanghai",
    "ui_version":"1"
  }
}
```

export_kind=view 对应 PNG，package 对应 ZIP。scope.type=batch／filtered／sample；sample 要求恰好一个 trace_id；batch 忽略当前来源筛选并明确导出批次；filtered 用 source_id、issue_type、q 重建服务端筛选，冻结为实际样本集合。禁止相信前端传入的总数；scope 中 trace_ids 只用于 sample 或已明确的有界选择，上限 100，不能传整批海量 ID。

contents 可包括 ingest_png、statistics_png、execution_png、tools_png、normalized_json、offline_html、evidence_index、manifest、error_report；原始日志 raw_files 需要单独权限且默认不选。view 导出只选择匹配 view 的 PNG。package 可选多项，manifest 强制包含。未生成的图、不可访问的原文或未经实现的渲染器，在 R02.export_options 中 availability=unavailable，附 reason；提交不允许项返回 422，不能静默忽略。

导出服务端从固定 snapshot、筛选和事件选择重建分析画布，包含上下文，不含平台导航和操作按钮；PNG 默认导出完整画布，不定义为浏览器任意滚动位置截图。ui_version 标识模板版本，服务端不接受任意 HTML 或脚本。后端 PNG 渲染器未完成时，该选项在 HTTP 模式明确不可用；Mock 可使用本地 canvas／SVG 合法渲染实现同语义。

导出 result：kind=agent_trace_export、batch_id、snapshot_id、scope_summary、included_contents、omitted_contents、artifacts[]；每项 artifact 包含第 3 节产物字段。omitted_contents 只可记录用户已知的“部分可用”项及受影响原因，不能偷删用户选择的必需项。权限或脱敏强约束不满足则失败。

R08 轮询建议 pending/running 时 2 秒起步、最大 10 秒退避，可提供 retry_after_ms；503／429 尊重 Retry-After；客户端退出停止轮询不取消后台任务。任务创建后 input 与操作人可供留痕；完整日志不要直接放任务列表。

summary 最低字段：

```json
{
  "file_count":2,
  "supported_format_count":3,
  "imported_format_count":2,
  "parsed_trace_count":200,
  "failed_record_count":0,
  "by_language":[{"code":"zh","count":100},{"code":"en","count":100}],
  "category_mode":"single",
  "by_category":[
    {"code":"prompt_injection","label":"提示注入","count":40},
    {"code":"unauthorized_access","label":"越权访问","count":36},
    {"code":"privacy_leak","label":"隐私泄露","count":32},
    {"code":"harmful_content","label":"有害内容","count":28},
    {"code":"tool_misuse","label":"工具滥用","count":34},
    {"code":"other","label":"其他","count":30}
  ],
  "by_format":[
    {"code":"openai_messages","file_count":1,"trace_count":100},
    {"code":"langchain_trace","file_count":1,"trace_count":100}
  ]
}
```

file_count 是当前快照实际参与解析的文件数量，staging 文件单独标注。JSONL 每行是否等于轨迹由适配器规范决定；不能把一条消息、一条 Span、一次工具调用直接当成完整轨迹。失败记录不一定能识别出轨迹数量，所以 failed_record_count 不叫失败轨迹数；已知 input_candidate_count 时才显示成功／候选总量。

类别为单标签时各类数量之和等于已解析轨迹数，未分类计入 other 或显式 unknown。若采用多标签则 category_mode=multi，UI 改为标签命中次数且不要求合计 200。测试标签与风险审计结果严格分开。

validation：

```json
{
  "scope":"trace_sample",
  "trace_total":200,
  "metrics":[
    {"code":"structure","passed":200,"eligible":200,"missing":0,"failed":0,"not_applicable":0,"state":"verified"},
    {"code":"call_link","passed":200,"eligible":200,"missing":0,"failed":0,"not_applicable":0,"state":"verified"},
    {"code":"time","passed":192,"eligible":200,"missing":8,"failed":0,"not_applicable":0,"state":"missing"},
    {"code":"usage","passed":160,"eligible":200,"missing":40,"failed":0,"not_applicable":0,"state":"missing"}
  ],
  "can_continue":true,
  "blockers":[],
  "failed_record_count":0,
  "issue_trace_count_distinct":44
}
```

这里 distinct=44 仅为本说明演示数据集的明确设定：8 条时间缺失与 40 条用量缺失交集 4 条，所以并集 44。截图不需要显示该数；真实返回应按轨迹去重计算，不能直接写成 48。

- 每个 metric 满足 passed + missing + failed = eligible；eligible + not_applicable = trace_total。eligible=0 显示不适用，不给绿色“全通过”。
- 结构有效在已发布标准化轨迹中检查，不把完全无法解析的坏记录塞进分母；坏记录通过文件错误和 failed_record_count 展示。
- 调用关联按轨迹汇总底层调用／返回检查。没有工具调用的轨迹标 not_applicable；有未配对、重复 call_id 等问题为 failed。截图所有轨迹均适用，故是 200/200，不能称为 200 次调用。
- 时间信息完整用于可计算任务时长：同一次运行有可靠开始结束或权威时长，单位和时区一致。按完整时间的 192 条计算时长；不可把消息序号推算为时间。
- 用量信息完整定义为该轨迹可归属且无重复计数的输入与输出 Token 统计；total 可由其相加派生，推理 Token 是单独可选子项，禁止再次叠加导致双计。完整性及来源写入 schema_version；部分字段可展示，但不进入需要完整值的平均值分母。截图平均 Token 覆盖 160 条，不是 200 条。
- reasoning 内容、可见摘要和 reasoning Token 三者不同，不用“摘要未提供”替代 usage_missing，不补造隐藏思考。
- can_continue 取决于至少有有效标准化轨迹、权限与有效快照；时间／用量缺失是非阻塞提示，结构不可用等可阻止特定分析并返回原因。数据完整不代表内容安全。

issues 每项包含 code、severity、affected_trace_count、impact、examples[]。examples 每项含 trace_id、display_id、source_id、snapshot_id、source_ref；支持批次级问题定位到其他来源。time_missing 示例 AUD-0081、AUD-0117；usage_missing 示例 AUD-0049、AUD-0076。示例必须真正在对应集合内，不能仅返回写死编号。

## 12 各来源适配细则

1. JSON／JSONL 仅是容器。结构识别要验证核心字段；歧义时返回 ambiguous 与候选格式，手动覆盖也必须做结构校验。
2. OpenAI 消息工具调用从消息内 tool_calls 生成调用事件；工具返回按 tool_call_id 匹配，function.arguments 保留原字符串并尝试解析。字符串解析失败记录错误路径，不覆盖原文。
3. LangChain／LangSmith Trace 将运行节点与父节点、类型、输入输出标准化；不要把每个 run 无条件当成完整轨迹。依据根运行或明确分组规则形成轨迹，保留 run_id 与 parent_run_id 来源。
4. Anthropic Messages 区分消息与 content block，工具调用与返回通过对应工具标识关联；多内容块可拆成多个事件，保留 block_index。不因系统“支持”就显示本批次“已接入”。
5. 三种适配器支持的具体输入 schema、导出版本与边界要在 formats 中声明并提供有效例子。平台导出的请求消息不一定自带时间或 Token；没有的字段标 not_provided。
6. call_id 唯一性限定在轨迹内；多个并行调用按标识配对，不按返回相邻顺序。事件 ordinal 记录顺序，parent_event_id 只记录可证实父子关系。
7. 原始证据不可修改；脱敏副本与原文版本关联。跨批次、跨快照的 trace_id／call_id 不做未经校验的全局关联。

## 13 R09 下载票据及文件输出

请求体 `{}`，X-Request-Id 必填；服务端校验 artifact 可用、未过期、属于当前用户有权查看的批次快照，记录下载审计。

```json
{
  "artifact_id":"art_001",
  "download_url":"/api/v1/files/download?t=opaque-short-lived-token",
  "expires_at":"2026-11-06T15:00:00+08:00",
  "filename":"agent-trace-result.zip",
  "mime_type":"application/zip",
  "size_bytes":123456,
  "sha256":"hex-digest",
  "authorization_mode":"ticket"
}
```

download_url 由文件服务签发，具体字节下载地址是票据内容，不增加一个本页手写的任意路径 API。URL 必须是配置的同源或受信文件域，短时限、限定产物与操作者；跨域时配置必要的 CORS。前端不能把 Bearer 转发到任意外链。字节下载响应本身不包 JSON envelope，使用正确 Content-Type、Content-Disposition 与文件名编码；正常接口的共享 request 只处理票据 JSON。

票据过期可重新申请；产物已删除返回 410 或平台等效状态，提示重新导出。标准 PNG、ZIP、JSON、HTML 的扩展名与 MIME、真实字节一致。ZIP 条目名规范化，禁止绝对路径和 ../；HTML 为离线资源，不依赖登录后的平台 API。

manifest 包含批次／快照／schema／adapter／模板版本、生成时间、导出范围与实际样本数、脱敏策略、匿名映射策略标识、实际产物列表、哈希、缺失数据说明和已知省略项。匿名 ID 在同包图片、HTML、JSON、索引中一致，不输出可反推的原 ID 映射；原始日志默认不导出。脱敏先于图片渲染，不能只脱敏 JSON。

## 14 错误与状态矩阵

| HTTP | 示例原因 | 前端预期 |
| --- | --- | --- |
| 400／422 | 格式覆盖无效、范围缺参数、不支持导出项、参数类型错误 | 定位表单项；不重试坏参数 |
| 401 | Token 失效 | 走共享登录跳转，清理敏感视图 |
| 403 | 无批次／原文／导出权限 | 显示无权限，不切到 Mock |
| 404 | 文件／批次／样本／事件不存在 | 清空对应预览，不选替代真实记录 |
| 409 | 版本冲突、上下文不匹配、解析任务竞争、幂等键冲突 | 展示原因和最新版本／已有任务；用户刷新后重试 |
| 410 | 快照或产物已按保留策略过期 | 提示重新解析或重新导出，不静默使用新快照 |
| 413／415 | 文件过大／容器不支持 | 上传行显示具体错误 |
| 429／503 | 限流／服务暂不可用 | 遵从 Retry-After、有界退避；保留上下文 |
| 500 | 系统异常 | 可重试错误和请求追踪号，不返回原文／堆栈／密钥 |

## 15 联调验收清单

- 旧合规和任务接口不破坏；HTTP envelope、大小写转换、认证和分页一致。
- 首屏 R02 聚合＋R06 详情即可渲染；不为 200 条轨迹逐条请求，不为六类数值发六次请求。
- 2 文件／2 已接入格式／3 支持格式／200 轨迹能同时成立；Anthropic 未导入不计入校验。
- q、issue_type、分页、前后导航范围一致；来源过滤不改变批次汇总。
- 原文、source_ref、选中事件与映射规则可核对，任意 JSON 字段未被转换。
- 批量绑定原子、解析提交幂等、运行中版本固定、发布快照原子、重复解析不叠加。
- 缺失时间和用量不当作 0；分母、交集和不适用数量准确。
- 导出权限、范围、脱敏、匿名化、文件格式、票据过期和离线打开均可验证。

## 16 DTO 补充约束和可解析样例

### 16.1 可用性和指标来源

轨迹 availability 和事件 availability 使用 available、partial、not_provided、not_applicable、invalid。校验 metric.state 沿用合规 VerificationState：verified、missing、unavailable、not_applicable、unknown。二者用途不同，不相互混用。任务状态独立使用平台 TaskStatus。

token_usage 如存在，结构为 input_tokens、output_tokens、total_tokens、reasoning_tokens、source_level、source_path、measurement、is_derived。其中前三项为非负整数或 null；reasoning_tokens 可选且不可重复加总；source_level=trace／run／message，measurement=provider／recorded／estimated。估算值单独展示，不默认进入“实际用量”平均值。只有根运行统计时不虚构每条工具事件的 Token。total_tokens 若由 input+output 派生，标记 is_derived=true。

时间来源建议返回 time_source={source_level, source_path, measurement}；duration_ms 可源自权威统计或可靠起止差，明确 measurement=recorded／derived。没有足够证据时不按步骤数估算。

issues 示例对象：

```json
{
  "code":"time_missing",
  "severity":"advisory",
  "affected_trace_count":8,
  "impact":"影响耗时统计，缺失样本不计入时长指标",
  "examples":[{
    "trace_id":"trc_0081",
    "display_id":"AUD-0081",
    "source_id":"file_001",
    "snapshot_id":"snap_001",
    "source_ref":{"source_id":"file_001","record_index":81,"source_path":"metadata.started_at"}
  }]
}
```

allowed_actions 为服务端授权动作数组，例如 upload、bind_files、parse、view_raw、export_view、export_package、export_raw；前端用于禁用操作，后端每次仍复核。这里只是本模块动作命名，不替换平台既有权限体系，后端可通过适配映射到原权限编码。

R02.export_options 至少包含 scopes、contents、redaction_profiles、anonymize_required；contents 每项为 code、availability、reason、supported_scopes。availability=available／partial／unavailable。部分可用项需要 available_count、requested_count、missing_reason；服务端生成时再次核验。

formats.example_text 直接包含对应文本字符串。标准化 input_json 和 output_json 仍用字符串，源文件内部原生 input 对象不受影响。示例应通过容器解析、结构识别、调用关联和字段定位四项检查后再提供给页面。

## 2026-11-08 当前实现接口核对与自动下载补充

本节按当前页面、API 适配器、store/composable 和 TypeScript DTO 核对，区分现有调用与规划扩展；与前文历史交互描述冲突时以本节为准。接口齐备指前端调用及交接契约覆盖，不代表真实后端已经部署或完成联调。

### 当前视图导出闭环

1. `POST /tasks/execute`，`capability_code=agent_trace_export`。快速返回 JSON envelope 内的 Task，不直接返回文件。随后通过 `GET /tasks/{task_id}` 查询；立即成功和异步成功必须使用同一结果结构。
2. `pending/running` 返回 `progress`（0—100，未知可 null）；`failed/cancelled` 返回可展示的 `error_message`。仅文件已经生成并可读取时返回 `succeeded`、`progress=100`。同一任务的终态与产物 ID 保持稳定。
3. 成功结果必须含 `result.kind=agent_trace_export`、`batch_id`、`snapshot_id`、非空 `artifacts`。当前视图应返回一个 PNG 产物，字段至少为 `artifact_id/filename/mime_type/batch_id/snapshot_id`；生产还应返回实际 `size_bytes/sha256/expires_at`。PNG 的 MIME 为 `image/png`，文件内容必须是真实 PNG。
4. **最终代码流程已变更**：Task 成功且 artifacts 非空后，由 ViewExportStatus 调用 tracePagePng，对浏览器当前 .agent-traces DOM 生成 PNG，再以本地 Blob URL 自动下载。此入口目前不调用 download prop、不领取 download-tickets，也不读取后端 PNG 字节；artifacts[0].filename 仅参与文件命名。真实模式仍先提交/查询真实任务；Mock 模式使用演示任务。因此后端任务和渲染能力仍是入口前置依赖，不能因本地截图就省略任务接口或伪造成功产物。
5. ZIP 结果包及其他原有文件下载继续使用票据协议：POST download-tickets、body={}，返回 download_url/filename/expires_at，再 GET 同源字节流。文件 GET 使用 fetch(credentials=same-origin)，不添加 Bearer；需票据 URL 或会话授权，失败返回非 2xx。文件内容不是 JSON envelope，下载地址不能是磁盘路径或登录 HTML。
6. 当前状态栏将后端任务进度映射到 0—70%，本地 DOM 复制/图片编码为后续阶段，触发下载后到 100%；这不是后端 progress 原值，也不表示浏览器磁盘落盘已验证。后端仍只返回自己的真实 progress，不需改为页面组合百分比。

验收应分别验证真实任务、浏览器 PNG 和后端产物：任务失败/空 artifacts 不生成页面图；重复终态不重复下载；本地图片含 Canvas/SVG 和当前展示内容；ZIP 的票据 403/410 与字节流失败独立验证。截图完整性不等于后端 PNG 模板一致性，HTTP 联调必须关闭示例模式。

### 接入与校验页实际调用补齐

现有 R01—R09 已覆盖上传、创建批次、绑定/格式覆盖、解析、工作区、来源/样本分页、事件/原文/映射、导出及下载，不需要增加领域路由。无 view 的读取仍按 ingest 解释，不得因新增其他三页投影而破坏原协议。

当前视图提交 `input.view=ingest, export_kind=view, format=png, contents=[ingest_png]`；顶层包含 `batch_id/snapshot_id/selected_trace_id/selected_event_id`。`scope={type:filtered,source_id,trace_ids,issue_type,q}`，空筛选可能为 null，trace_ids 为当前选中样本的单项数组或空数组。服务端按来源/问题范围解释 filtered，并用 selected_trace_id 定位预览，不能因为携带当前 trace_ids 就把整个汇总范围缩为单样本。汇总仍使用整批快照。

结果包 `scope.type=batch/filtered/sample`，contents 来自工作区可用项并强制加 manifest；`batch` 忽略来源和问题过滤，`sample` 必须验证当前样本。公共参数为 `redaction_profile=standard, anonymize_ids=true, locale=zh-CN, timezone=Asia/Shanghai, ui_version=1`。本页当前不发送 ui_state，后端不得将其新增为必填；按已提交选择和固定快照生成视图。

格式示例由 workspace.formats[].example_text 提供；格式下载/当前片段复制属于前端本地操作，不需要额外后端接口。原文、标准化和映射必须来自同一详情及选中事件。工作区 export_options 必须声明 ingest_png 的 availability；未部署渲染服务时明确 unavailable，不能仅凭导出权限就承诺有效 PNG。

## 最终页面逐操作对接清单（2026-11-08 复核）

所有路径相对 /api/v1，JSON 传输用 snake_case。以下是当前实际消费约束，不只描述目标领域模型。

| 页面动作 | 请求与响应落点 |
| --- | --- |
| 首次进入、切批次/来源、定位问题 | GET workspace，传当前 Query；读取 resolved_selection 后再 GET 所选样本详情。resolved_selection 必须始终为对象，空批次各 ID 为 null |
| 搜索来源/批次选项 | GET workspace，沿用当前上下文并附 option_q/option_page/batch_option_page；当前只替换 source_options/batch_options，不应改变已查询快照 |
| 搜索样本、列表翻页 | GET batches/{batch_id}/samples，沿用 snapshot_id/source_id/issue_type，附 q/page/page_size；返回完整 PageResult |
| 选样本、选事件、事件翻页 | GET samples/{trace_id}，附 event_id/event_page/event_types；即使只切事件仍返回完整 Detail，不是裸事件对象 |
| 上一条/下一条、问题示例定位 | 使用 navigation 或 issues.examples 返回的 trace_id/source_id/page；必须是真实内部标识，不能只给展示编号 |
| 上传与识别格式 | POST /files 返回 file_id，再 POST batches/{batch_id}/files，传 expected_version 和 files[{file_id,format_override}]；绑定后重新 GET workspace |
| 新建批次 | POST batches，body={name}，返回 Batch，前端用 batch_id 重新加载工作区 |
| 开始解析/重新解析 | POST /tasks/execute，input={batch_id,expected_version,mode}；不保证传 file_ids，服务端根据批次版本及 mode 确定文件集 |
| 查看格式示例、复制当前原文 | 前端使用已取得的 example_text/raw_text，不另发请求 |

详情必须回显 batch_id/snapshot_id/trace_id/source_id，前端逐项比较，不一致直接拒绝展示原文。issues 筛选会移除来源约束，服务端应返回全批次对应问题样本，不能继续隐式限制旧来源。旧 Query 中可能附 trace_id/event_id/event_page 等上下文字段；列表只按本接口相关字段筛选，不应将保留的选中 trace_id 当作列表仅一条的条件。

空 workspace 仍应返回 formats、upload_policy、各分页对象、summary、validation、issues、export_options、active_tasks，不能整包 data=null。空详情事件返回 normalized_event=null、events.items=[]、mapping.rows=[]；真实缺失与格式错误应通过错误或可用性说明表达，不能省略结构使组件访问失败。

当前导出按钮启用条件为存在 batch.active_snapshot_id 且 validation.can_continue=true，并且没有运行中的操作；PNG 还要求 export_options.contents 中 ingest_png 的 availability=available。当前组件未读取 batch.allowed_actions 的 export 权限，后端必须在提交、任务读取、票据和下载阶段实际校验授权；细粒度按钮权限需后续前端接入，不能将其描述为已实现。

当前解析按钮提交 mode=parse_pending；“重试失败”提交 mode=retry_failed。后端应分别处理待解析文件和失败文件，幂等命中不得重复发布快照。上传成功返回 file_id 不代表绑定或解析成功；任一步失败均需明确保留前一阶段状态。
