# 内容安全治理平台生产部署计划书

## 1. 目标与范围

将当前 Vue 前端、FastAPI 后端和 MySQL 数据库部署到一台可公网访问的服务器，并通过一个 HTTPS 域名提供服务。

目标访问链路：

```text
用户浏览器
  -> https://example.com
  -> Nginx
     ├─ /           -> Vue 前端 dist 静态文件
     └─ /api/v1/*   -> FastAPI（127.0.0.1:8000）
                         -> MySQL（仅服务器内网访问）
```

本计划不包含真实模型训练、真实模型部署和神经元激活采集能力的研发；这些功能即使页面存在，也需要额外的模型服务或计算基础设施。

## 2. 当前基础

- 前端可构建为 `dist` 静态文件。
- 前端已采用相对接口地址 `/api/v1`，适合与后端同域部署。
- 后端已有 FastAPI 入口、`/health` 健康检查、MySQL 配置读取及数据库初始化逻辑。
- 前端真实模式配置已存在：`VITE_USE_MOCK=false`、`VITE_COMPLIANCE_DEMO=false`、`VITE_SCENARIO_DEMO=false`。
- 后端 MySQL 配置文件为 `back/.env`，且已被 Git 忽略。

## 3. 实施计划

### 阶段一：准备服务器与域名

1. 准备 Linux 云服务器，建议 Ubuntu 22.04 或 24.04。
2. 安全组或防火墙仅开放：
   - `22`：SSH 运维访问，应限制来源 IP。
   - `80`：HTTP，用于证书签发和自动跳转 HTTPS。
   - `443`：HTTPS，对外网站访问。
3. 不对公网开放 `8000`（FastAPI）和 `3306`（MySQL）。
4. 购买或准备域名，新增 DNS A 记录，指向服务器公网 IP。
5. 安装基础软件：Nginx、Git、Python 3.12+、uv、Node.js、MySQL 8。

验收标准：使用域名可解析到服务器；服务器仅暴露预期端口。

### 阶段二：配置数据库

1. 创建专用数据库，例如 `content_safety`。
2. 创建专用应用账号，不使用 MySQL `root` 账号运行服务。
3. 授予该账号仅对业务数据库的必要权限。
4. 在服务器项目目录的 `back/.env` 中填入 MySQL 信息：

```env
MYSQL_HOST=127.0.0.1
MYSQL_PORT=3306
MYSQL_USER=content_safety_app
MYSQL_PASSWORD=请使用高强度密码
MYSQL_DATABASE=content_safety
```

5. 设置文件权限，确保仅部署账号可读取 `back/.env`。
6. 制定每日自动备份策略，并至少执行一次恢复演练。

验收标准：后端启动日志显示 MySQL 连接成功；`/health` 返回正常；数据库账号不可访问其他数据库。

### 阶段三：部署并常驻运行后端

1. 将项目代码放到服务器固定目录，例如 `/opt/content-security-platform`。
2. 在 `back` 目录运行 `uv sync` 安装锁定版本的依赖。
3. 创建 systemd 服务，以生产方式运行 Uvicorn，不使用 `--reload`。
4. 服务应绑定 `127.0.0.1:8000`，只允许 Nginx 在本机访问。
5. 配置开机自启、异常自动重启及日志查看方式。

建议启动命令：

```bash
cd /opt/content-security-platform/back
uv run uvicorn app.main:app --host 127.0.0.1 --port 8000
```

验收标准：服务器重启后后端自动恢复；`curl http://127.0.0.1:8000/health` 返回成功；公网无法直接访问 `:8000`。

### 阶段四：构建并部署前端

1. 确认项目根目录 `.env.local` 使用真实模式：

```env
VITE_USE_MOCK=false
VITE_COMPLIANCE_DEMO=false
VITE_SCENARIO_DEMO=false
```

2. 安装依赖并构建：

```bash
npm ci
npm run build
```

3. 将生成的 `dist` 作为 Nginx 网站根目录。
4. 不要把 `.env.local`、`back/.env`、虚拟环境或数据库备份暴露为静态文件。

验收标准：访问域名首页可加载页面；刷新任意 Vue 路由不会出现 Nginx 404。

### 阶段五：配置 Nginx、域名与 HTTPS

1. 配置 Nginx：
   - 网站根目录指向前端 `dist`。
   - 前端路由使用 `try_files $uri $uri/ /index.html`。
   - `/api/` 反向代理到 `http://127.0.0.1:8000`。
   - 上传接口配置与业务相符的请求体大小和超时。
2. 使用 Let's Encrypt / Certbot 签发 HTTPS 证书。
3. 将 HTTP 强制跳转 HTTPS。
4. 配置证书自动续期。

验收标准：

- `https://域名/` 正常打开且浏览器无证书警告。
- `https://域名/api/v1/…` 能由 Nginx 正确转发至后端。
- Vue 任意子路由刷新正常。
- HTTP 自动跳转 HTTPS。

### 阶段六：认证、权限与安全加固

当前代码会在浏览器中读取 `accessToken` 并发送 Authorization 请求头，但后端尚未看到统一的强制认证和权限校验。因此在开放给非受信任用户前必须完成以下事项：

1. 实现登录、退出、令牌签发与过期刷新机制。
2. 在 FastAPI 的路由或依赖层强制校验身份，不能只依赖前端隐藏菜单或按钮。
3. 按用户、角色或组织范围限制数据读取、文件下载、模型配置和管理操作。
4. 保护高风险接口：文件上传、外部数据库接入、模型服务登记、任务执行与系统管理。
5. 为密码、令牌、数据库连接串配置服务端密钥管理；禁止写入前端构建产物。
6. 配置访问日志、异常日志、操作审计和基本限流。

验收标准：未登录请求受保护接口返回 401；越权请求返回 403；普通用户无法读取或修改其他用户的敏感数据。

### 阶段七：处理演示数据与外部模型服务

1. 逐页核对真实模式下的接口是否都由数据库或真实业务服务返回。
2. 将“合规风险审计”中的本地评论与错误档案改为后端持久化接口。
3. 对场景应用确认部署策略：
   - 若使用独立模型服务，需要部署或连接该服务，并由 Nginx 配置 `/llm-api` 转发；或
   - 将模型调用改为仅由业务后端发起，避免浏览器直接接触模型服务凭据。
4. 对仍为静态展示的算力、存储、网络等卡片明确标识为说明内容，或补充真实监控接口。

验收标准：关闭所有演示开关后，关键业务页面不返回 `src/mock` 数据；失败时显示真实错误而不是伪造成功结果。

## 4. 上线验收清单

- [ ] 域名 DNS 生效，HTTPS 可访问。
- [ ] 前端首页、主要路由和浏览器刷新均正常。
- [ ] `/health` 和关键 API 经域名访问正常。
- [ ] MySQL 仅内网访问，且已完成备份与恢复测试。
- [ ] FastAPI 由 systemd 常驻并开机自启。
- [ ] `8000`、`3306` 未对公网开放。
- [ ] 真实模式关闭所有 Mock/演示开关。
- [ ] 登录、权限与越权访问测试通过。
- [ ] 上传、任务执行、数据库异常和模型服务异常均有可读错误提示。
- [ ] 记录当前发布版本、数据库备份点和回滚版本。

## 5. 日常发布与回滚

### 常规发布

```text
本地修改并测试
  -> 提交 Git
  -> 服务器拉取指定提交
  -> 前端 npm ci（仅依赖变化时）与 npm run build
  -> 后端 uv sync（仅 Python 依赖变化时）
  -> systemctl restart 后端服务
  -> 验证首页、健康检查与核心接口
```

### 回滚原则

1. 每次发布记录 Git 提交号和数据库备份时间。
2. 页面或后端代码异常时，回退到上一稳定 Git 提交并重新构建、重启服务。
3. 涉及表结构变更时，必须先备份数据库；表结构迁移应可回退。
4. 不使用删除数据库或覆盖生产数据的方式回滚应用代码。

## 6. 后续改进建议

1. 引入 Alembic 管理数据库迁移，替代生产环境启动时的自动改表逻辑。
2. 使用 Gunicorn/Uvicorn Worker、systemd 或容器编排实现明确的生产进程管理。
3. 建立 CI/CD：推送代码后自动测试、构建并在审批后发布。
4. 增加监控告警：服务器资源、接口错误率、数据库连接、磁盘容量与证书到期时间。
5. 建立发布前自动化冒烟测试，至少覆盖首页、登录、关键查询、文件上传和任务创建。
