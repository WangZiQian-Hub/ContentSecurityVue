# 智能体轨迹审计后端接入指南

## 当前交付与联调入口

前端已新增 `/compliance/agent-traces`。真实请求代码为 `src/api/agent-traces.ts`，精确 DTO 为 `src/types/agent-traces.ts`；演示服务位于 `src/mock/agent-traces.ts`，用于理解页面消费方式，不应部署为后端算法。

本次未修改任何后端代码。请保持平台既有合规接口、任务接口与上传接口兼容。不要用 `/compliance/traces/{id}` 代替本页详情，它是另一种平台溯源模型。

## 优先对接顺序

1. 实现聚合 workspace 和 sample detail，先跑通已有批次只读展示。
2. 实现批次创建与文件批量绑定，复用上传服务。
3. 注册 agent_trace_ingest 能力，接统一任务执行和任务查询；解析后原子发布快照。
4. 实现样本列表分页、问题筛选与导航，验证范围和缺失分母。
5. 注册 agent_trace_export 能力、产物存储、下载票据；PNG 渲染尚未提供时，将对应 exportOptions 标 unavailable，不返回虚假产物。

## 共享协议必须一致

JSON envelope 为 code/message/data/trace_id/timestamp，成功 code=0；wire 使用 snake_case，前端自动变 camelCase。POST 带 X-Request-Id，按相同键和载荷返回相同结果；同键不同载荷 409。Bearer 与 Request／Trace ID 使用平台公共封装。分页为 items/total/page/page_size/total_pages，page 从 1 开始。

envelope.trace_id 是请求追踪号；data 中的 trace_id 是业务轨迹号，不能混用。display_id 仅用于显示，不拿它代替内部 ID 查表。样本的 source_id 引用上传文件资产 file_id。

原始 JSON、工具任意参数与输出必须分别放 raw_text、input_json、output_json 字符串内；路径字符串不改写。前端不会绕开公共转换器去恢复已被服务端错误对象包装改写的字段。

## Workspace 的最小闭环

必须返回 resolved_selection、formats、upload_policy、source_options、batch_options、batch、files、summary、validation、issues、sample_page、export_options、active_tasks。前端访问列表的 items，不接受把分页字段替换为 rows 或 records。

formats 每项包含 code、label、containers、description、availability、schema_version、example_text。summary 同时给 supported_format_count 与 imported_format_count；by_format、by_language、by_category 使用数组，不使用动态键对象。字段命名应严格照契约，空项使用空数组而不是 null。

首次请求未指定上下文可解析默认选择；精确指定的不合法上下文应报错。已解析轨迹和待解析文件分开：staging_changed=true 提示正在等待解析，不能提前改变成功轨迹总量。active_tasks 应限定当前批次，刷新页面可以恢复轮询。

## Detail 的最小闭环

一次返回原文、当前事件、目录分页、映射、来源和导航，不需要给每个字段单独接口。必须回显 batch_id/snapshot_id/source_id/trace_id，前端核验不匹配即拒绝展示。

raw_preview 至少有 raw_text、kind、truncated、line_start、total_lines；source_ref 有 source_path、record_index；events 为 PageResult；normalized_event 为当前事件或 null；mapping 有 format_label 和 rows，行含 source_path、target_path、description、state；navigation.previous/next 为包含 trace_id/source_id/page 的定位对象或 null。

event_types=tool_call,tool_result 用于工具交互服务端目录过滤。无工具调用返回空目录，不冒充一次成功调用；普通页和执行页可读取完整事件目录。前端不会把截图中三条消息当成完整 18 步。

## 解析与导出结果

开始解析按批次和 mode 处理整个符合条件的集合：当前实现省略 file_ids，表示服务端在冻结的 expected_version 中选择全部待解析／失败文件，不能只解析文件列表当前分页的 20 项。若调用方显式给出 file_ids，则处理该有界集合。此可选字段语义是对完整契约解析示例的补充，后端请同时支持两种形式。

平台状态只用 pending/running/succeeded/failed/cancelled。部分记录失败是 succeeded + result.outcome=partial；不要新造平台不认识的 partial_success。解析 result 带 kind=agent_trace_ingest、batch_id、snapshot_id 和 outcome，前端成功后重新请求 Workspace。

导出 result 带 kind=agent_trace_export、batch_id、snapshot_id、artifacts[]，每项至少 artifact_id、filename、mime_type、batch_id、snapshot_id。当前视图任务成功后前端本地绘制页面 PNG 并自动下载，不调用 R09；结果包仍保留票据下载按钮。下载二进制不包 envelope；票据 JSON 才包 envelope。

当前页面只信任同源下载地址，不向任意外链附加 Bearer。若生产要使用跨域对象存储，请先提供明确域名白名单方案，保持票据限时、限定产物，不能直接放开所有 URL。CORS 与文件名编码由文件服务处理。

默认脱敏与匿名化适用于所有产物。当前 Mock 结果包包含标准化 JSON、离线 HTML、证据索引、manifest 和错误摘要；图片为本地摘要画布。后端应按完整契约提供真正的分析画布渲染和详细 manifest，不能把 Mock 简化报告当生产报告标准。

## 联调检查样例

基准批次为 2 文件、200 条轨迹，中文与英文各 100；OpenAI 和 LangChain 各 100，Anthropic 支持但未接入。结构与调用关联 200/200，时间 192/200，用量 160/200；二者缺失交集 4、并集 44。生产数量都应查询计算，不能按此样例写死。

调用关联按适用轨迹汇总，不是调用总数；无调用样本计入 not_applicable。时间与用量缺失不填 0，分别排除对应指标；Token 不是推理摘要。点击问题定位返回真实受影响样本，可以跨来源。切单个文件的 100 条预览，批次汇总仍是 200。

## 错误行为

401 由公共层回登录；403 展示无权限；404 清空对应详情；409 提示版本或上下文冲突；410 提示快照／产物已过期；413/415 指出文件限制；其他失败保留可重试错误。HTTP 模式不自动回落 Mock。

联调无需修改其他工程以外的前端接口约定；如必须调整契约，请同步 types、HTTP 和 Mock、页面消费以及本目录说明，不能只改后端返回字段后要求页面猜测。

## 最终代码：HTTP / Mock 模式与接口合理性审查

### 模式选择的实际规则

页面开关来自 compliance store 的 demo 状态，四个子页共同使用，不是各自独立的开关。界面明确显示“示例数据 · 独立设计演示，未连接后端”或“真实 HTTP 模式 · 数据与处置结果以服务端返回为准”。真实模式错误按错误展示，不自动改用 Mock。

默认 demo=true 的条件为：`VITE_COMPLIANCE_DEMO=true`；或开发环境中 `VITE_COMPLIANCE_DEMO` 与 `VITE_USE_MOCK` 均不为 false。生产环境默认不满足第二项。`VITE_USE_MOCK=true` 本身不保证生产环境进入演示；演示生产包应显式设置 `VITE_COMPLIANCE_DEMO=true`。测试真实接口建议同时设置 `VITE_COMPLIANCE_DEMO=false` 与 `VITE_USE_MOCK=false`，也可用界面开关明确切换；构建环境变量修改后需重新启动/构建。

| 子页 | 示例模式实现 | 真实模式实现 |
| --- | --- | --- |
| 接入与校验 | createAgentTraceMock，模拟上传、批次、解析、分页和导出 | agentTraceHttp，复用 /files、/tasks 及 agent-traces 领域接口 |
| 统计指标 | createAgentTraceStatisticsMock，桥接接入演示快照并使用统计示例数据 | agentTraceStatisticsHttp，GET statistics 及样本/任务/票据接口 |

| 工具交互 | toolsMock，演示调用、权限比较、时序、原文；导出本地生成 Blob | toolsHttp 查询；useExecutionExport 调用真实任务/票据 |

切换模式时各子页重新配置数据源、清理任务/详情等状态；演示 ID 不能用于真实资源。已发出的后台任务不因前端切换而自动取消。API 前缀来自 VITE_API_BASE_URL，默认 /api/v1；当前 Vite 开发代理将 /api 转发 http://127.0.0.1:8000。生产需部署同源反向代理或明确配置 API 地址；下载票据仍必须给浏览器页面同源地址。JSON 请求共享 Bearer/envelope/snake_case 转换，下载二进制走票据 URL。

### 合理性结论及尚未闭合项

接口按工作区聚合、分页列表、复合详情、公共异步任务与票据分工；四页通过 view 区分同资源的投影，统计首屏使用独立 statistics 资源。读取接口不执行解析/工具动作，解析与导出走能力任务。总体划分合理，已为后端保留可实现的请求层、DTO 和接入契约。

以下限制仍存在于当前前端，应列入联调问题而不能宣称全场景已保证：

- 思维路径精确深链未完整传递历史 snapshot/projection，目标不在初始样本页时可能不能精确选中，详见 execution 完整契约。
- 接入页未使用 allowed_actions 控制导出；思维/工具页未消费逐项 export_options。后端必须始终独立鉴权，后续前端才能完善按钮级能力控制。
- 工具页导出未传完整 ui_state，不能承诺 PNG 与当前加载段、调用分页完全一致；其余缺省值及渲染范围按 tools 文档处理。
- 工具指标未知值的展示、部分长内容/选项续页扩展尚未完整接入；不能让后端以虚假 0 或不完整数据冒充有效值。
- Mock 导出用于验证交互及合法文件格式；底层演示任务仍可生成文本画布，但当前用户实际下载的是浏览器 DOM 绘制的页面 PNG；这不证明真实服务端截图渲染已实现。

### 需要后续协同闭合的问题

1. PNG 任务仍要求后端提供合法产物及相应能力声明，但用户最终下载本地页面图；两份 PNG 的 hash/字节/范围可能不同，后端审计记录不能将本地图片误认作服务端产物。后续需明确产品是本地页面快照还是可追溯服务端报告，目前保留现有行为，不擅改接口。
2. 页面图在任务成功后读取当时 DOM，不是提交时冻结的 DOM；任务期间若用户改变样本、筛选或事件，后端任务 scope 与最终页面图可能不同。复制 DOM 期间也未整体锁定页面。对严格审计导出不能宣称范围完全冻结。
3. 本地页面图保留屏幕上当前展示内容，包括已授权原文、内部 ID、当前页和已加载片段；它不执行服务端 anonymize_ids/redaction_profile。不能承诺与后端脱敏产物完全一致，不能将预览截图当成全量数据包。
4. 思维路径历史版本/非首屏深链、部分细粒度权限能力控制、工具指标缺失状态、长内容续段等已知前端边界仍见各页主契约；本次复核未发现这些限制已被代码消除。
5. 成功状态仅证明本地图片生成且发起下载；真实鉴权、权限撤销、后端文件格式、票据失效和跨页版本一致性仍需真实服务联调。不得因为 Mock 可用就认定生产验收完成。

此轮只修订现有接口交接文档，没有修改页面代码。正式联调时先按对应页的最终调用清单实现，再逐项记录上述边界的解决情况。
