数据资源演示快照计算说明（供后端联调）
数据截止时间：2026-09-26 18:00:00 +08:00；六个数据集，五条接入任务，当前固定版本共 720 条演示样本。接口 generatedAt 为实际生成查询结果的时间。

1. 数据来源与关联
数据集目录在 src/mock/resource-catalog.ts，样本在 resource-samples.ts，接入任务在 resource-ingest.ts。数据集 id、versionId、任务 datasetId/datasetVersionId、样本 datasetId/versionId 必须一致。mock/data-resource.ts 仅导出这些数据；统计由 resource-statistics.ts 根据记录计算，不单独保存图表百分比。当前 6 个数据集各有 120 条可查询样本，合计 720 条。storageGb 是数据集登记的演示存储量，不是这 720 条文本的实测文件大小；后端应以版本存储清单或计量记录提供真实值。

2. 本快照的可核算结果
数据集数 6，可用 5，处理中 1，低质量 1；可用占比 = 5 / 6 = 83.3%。登记存储量合计 3712.0 GB，记录数 = 6 × 120 = 720。来源名称去重后为 5 类。
任务数 5：成功 2、运行中 2、失败 1。已结束任务成功率 = 2 / (2 + 1) = 66.7%；运行中任务不进入分母。空分母返回 displayValue“—”，不可解释为 0% 成功率。
语种标签出现 10 次：中文 6、英文 3、日文 1，占比 60%、30%、10%。模态标签出现 8 次：文本 5、图片 1、视频 2，占比 62.5%、12.5%、25%。同一数据集内重复标签只计一次；这些比例不是样本条数或存储字节的构成比。
来源分布以各数据集 storageGb 按 sourceName 汇总，分母 3712.0 GB。每个数据集的七条 storageEvents 加总恰好等于其 storageGb；按事件日期合并得到每日新增量，累计量为该日及以前全部已登记事件的和，末日累计 3712.0 GB。事件是演示快照记录，不应从当前总量倒推历史。
六个数据集分别保存五项质量维度，五项的算术均值等于该数据集 qualityScore。综合评分是六个 qualityScore 的算术均值 89.8；雷达图每个维度分别对选中数据集取算术均值。质量问题按类别直接相加：缺失字段 25、重复记录 15、格式异常 10、低置信度 9。同一记录可能有多类问题，问题总数不可当作不合格记录数。
使用排行依据各数据集 usageCount（85、67、41、33、19、12），合计 257 次；每行占比 = 该集次数 / 当前筛选集合的总次数。该数值代表演示使用审计计数，不代表接入任务数。

3. 筛选和百分比规则
GET /data-resources/summary 的 view 为 overview、ingest、datasets 或 statistics，startDate/endDate 按数据集 createdAt 日期闭区间筛选，sourceType、language、datasetId 对数据集筛选。语种筛选表示数据集包含该标签；选中多语数据集后，它的全部语种标签仍参与图表。任务只统计 datasetId 属于筛选后集合的记录。趋势只汇总这些数据集的存储事件，再将事件日期限制在所选日期范围内；累计线包括该日期之前的已登记事件。
筛选选项 GET /data-resources/options 从全部授权数据集生成，不随本次筛选收缩。所有比值先按原始数量计算，再以最大余数法保留一位小数，确保同一分布的显示值合计 100%。若分母为零，图表为空；可用率和成功率卡片显示“—”。

4. 后端契约与核验
现有真实接口分支已保留：GET /data-resources/options、GET /data-resources/summary、GET /datasets、GET /datasets/{id}、GET /tasks?capabilityCode=data_ingest、GET /datasets/{id}/versions/{versionId}/samples，以及文件上传、任务执行、数据集写入接口。接入后端时设置 VITE_USE_MOCK=false；summary 应一次返回同一快照的 kpis、trend、modalities、sources、languages、quality、qualityScore、issues、ranking、filters、generatedAt、datasetIds、basis 和 options，供卡片、图表与 CSV 共用。请保证分页列表、详情、任务、版本样本与 summary 使用同一授权范围和快照时点。生产环境的存储事件、质量扫描明细、问题计数和使用次数应来自持久化记录；缺失时返回空数组并说明缺失，不用静态图值填充。

5. 演示数据的边界
六个数据集在 2026-09-20 创建，七天事件从 09-20 至 09-26。因此选择 09-20 至 09-26 可查看完整快照；日期筛选是“数据集创建日”，不是“发生过存储事件的日期”。演示质量、问题和使用计数是少量已保存的模拟审计记录，不声称由 720 条文本重新检测得到。需要样本级语种占比或真实质量结论时，后端还需提供逐样本标注及对应的检测结果。

6. 四个页面的日环比（2026-09-26 补充）
统一按天比较，北京时间每日 18:00 保存快照。本期 asOf = 2026-09-26T18:00:00+08:00，前期 = 2026-09-25T18:00:00+08:00，相隔 24 小时。不是小时环比，也不是用尚未结束的今天去比较昨天全天。generatedAt 仍只是本次查询生成时间，不能用它代替 asOf。生产后端每天生成最新完整快照及前一日同一时点快照；缺失前一日记录时不能拿更早某一天冒充。
历史明细在 src/mock/resource-kpi-history.ts：保存每个数据集的记录数、状态、质量状态，以及每条任务的状态。存储量由截至前期时点的事件历史求和。前后两期使用相同聚合函数，计算出两组 KPI 后再计算差值；文件中没有直接填写上升或下降百分比。
数量指标（个、类、条、GB）：（本期值 - 前期值）/ 前期值 × 100%。比例指标（可用占比、已结束任务成功率）：本期原始比例 - 前期原始比例，以“个百分点”显示。先对未舍入的原始比值计算变化，再保留一位小数；例如 5/6 与 4/6 的差应显示 +16.7 个百分点，不能先用 83.3 - 66.7 得出 16.6。

这里比较的是累计数量和时点状态。例如“接入任务”是截至快照时点的累计任务，不是一天内新建任务数；“运行中”是该时点运行中的任务数。昨日第五个数据集仍在处理中，第四、第五个数据集质量为 poor；今日第五个可用、第四个质量改善。昨日 task_4 仍在运行，今日成功；task_5 在 26 日才创建并失败，不能进入昨日任务集合。调整了现有任务的 createdAt，使其与历史状态的时间关系一致。
所有来源、语种、数据集和创建日期条件，在两期数据集快照上分别应用同一组条件。日期范围不自动向前平移；它筛选创建日期范围内的数据集，不改变每日快照时点。两期再分别按筛选后 datasetId 关联任务，不能把某个数据集的本期结果与全局前期结果比较。例：筛选业务数据且英文，只剩 dataset 1；存储量由 1580 -> 1860 GB，变化 +17.7%，不是全局 +17.5%。

边界和显示：数量前值为 0 且本值非 0 时，显示“新增（原为0）”，change=null，不能显示无穷大或假定 +100%；数量 0 -> 0 显示灰色“→ 0%”。任一期比例分母为 0 或历史缺失，变化为 null 并标明不可比。有效的 0% 比例可参与百分点相减。上升使用红色“↑ +”，下降使用绿色“↓ −”，不以颜色推断业务好坏；持平统一显示灰色“→ 0%”（比例指标的实际差值单位仍在 comparison.unit=pp 中保留）。具体比较时点、前值、公式显示在卡片悬停提示中。

接口扩展：GET /api/v1/data-resources/summary 保持现有请求参数，响应增加 as_of，并在每项 kpis 中增加 comparison。示例（后端 JSON 使用 snake_case）：
  {
    "id": "storage", "value": 3712, "unit": "GB", "change_rate": 17.5,
    "comparison": {
      "period": "day", "timezone": "Asia/Shanghai",
      "current_at": "2026-09-26T18:00:00+08:00",
      "previous_at": "2026-09-25T18:00:00+08:00",
      "previous_value": 3160, "change": 17.5, "unit": "%", "status": "available"
    }
  }
comparison.unit 取 %（相对变化）或 pp（百分点差），status 取 available、zero_baseline 或 unavailable。current_at 应等于 summary.as_of。previous_value 为前期已聚合的值，缺少有效值时为 null；change 为按原始数值计算再舍入的结果。旧 change_rate 保持相对变化率语义以兼容其他调用方；数据资源卡片以 comparison 为准，不能把比例指标的 change_rate 当作百分点差。后端未提供 comparison 时明确提示缺少历史快照，前端不会回退使用 mock 历史。CSV 导出包含相同环比、前值和两个时点。
