# 全链路合规治理：页面设计、组件数据与接口报告

版本：2026-09-27 / 精细设计版。交付包括 7 张页面图、2 张交互状态图，全部提供 1920×1080 和 3840×2160 PNG。图中业务记录均为设计示例，短 ID 是便于阅读的展示别名；正式系统须保存完整、稳定的真实 ID。

## 1. 设计结论与依据

本模块的职责是：**验证跨模块证据关系 → 审查训练与调用过程 → 查看内部审计产物 → 处置风险事件 → 核验完整证据链**。具体的数据清洗、样本修复、训练执行、模型调用、知识编辑、指标计算与场景运行继续由各自业务模块承担。

依据是用户提供的实施思路、课题映射文件、开发规范 01–07 和 README，以及压缩包主项目源码。文档中的建议作为设计输入；用户明确提出的“不重复、不增加无意义组件、不影响其他页面”优先于统一放置 4–6 个 KPI 卡等外观约定。因此本设计只在总览显示两项可行动的汇总，子页按对象展示证据，不机械重复指标栏。

已核实的代码事实：

## 2. 逻辑链与不重复边界

```text
数据资源：原始集 / 数据版本
    → 数据治理：处理任务 / 输出版本 / 已有风险结论
    → 模型训推：训练记录 / 检查点 / 模型版本
    → 模型调用：输入检测 / 模型调用 / 输出检测 / 治理后输出
    → 场景应用：场景任务 / 回执

合规模块读取这些事实：
总览定位交接缺口 → 谱系或训练审计找到证据断点
调用审计找到风险步骤 → 可关联内部激活证据
告警认领与补证 → 复核 → 全链路重新核验
测试评估引用审计证据，对项目指标作独立评价
```

历史训练通常发生在本次推理之前。整链页通过**模型版本的来源关系**联到历史训练、治理和数据记录；本次 Trace ID 只定位当前调用及其关联事件。历史记录保留原始 `trace_id` 和时间，不改写为当前 Trace ID，也不声称训练发生在本次请求内。

| 原页面 | 原页面拥有的内容 | 合规页新增的独有视角 |
|---|---|---|
| 综合态势 | 全平台概况、场景入口、最近业务任务 | 跨模块交接关系缺口、审计复核队列，不复制全平台 KPI |
| 数据资源 | 导入、数据集内容和版本管理 | 版本是否被正确引用，关系是否有可核验的证据 |
| 数据治理—价值分析 | 评分、归因、价值因果路径 | 工程依赖和版本流向；不把相关关系画成价值因果关系 |
| 数据治理—异常/风险 | 识别、样本修复、污染分析、风险分类 | 引用已有结果和任务证据，不再运行样本治理或复制分布图 |
| 模型训练 | 训练配置、loss/epoch、训练启停、产物 | 数据使用规则和检查点留痕，不重复 loss 曲线或训练表单 |
| 模型调用 | 调用输入、原回答、治理回答 | 一次调用各步骤时间、规则命中和证据引用，不重做聊天框 |
| 模型评估 | 知识编辑、能力保持与风险减少评价 | 内部激活捕获证据、异常单元定位，不提供模型编辑操作 |
| 测试评估 | 指标公式、阈值、通过率和测试报告 | 五要素证据核验与可引用材料；不代替指标验收 |
| 场景应用 | 场景治理执行与效果 | 场景输出回执是否关联完整，不复制场景操作面板 |
| 系统日志 | 全平台日志检索 | 仅展示当前证据对象关联的日志摘要和引用 |

“不重复”针对业务内容和职责；页面外壳、筛选控件、状态标签等基础 UI 可以一致，同一真实对象可以在不同审计视角中被引用，但不得复制整个业务工作台。

## 4. 每个组件的含义、来源和交互

标识：**B**＝后端事实或后端计算；**F**＝前端临时选择/格式化；**N**＝新增接口或新增结果字段，需要后端实现。下面 Q1–Q7 对应第 6 节接口。

### 4.1 总览

| 组件 | 意义 / 计算口径 | 来源与交互 |
|---|---|---|
| O1 核验范围、日期、快照时间 | 确定下方同一统计范围；页面刷新只重新查询 | 选择是 F，`as_of`/范围及全量计数是 B，Q1；时间范围采用服务端约定的 `[from,to)`。 |
| O2 跨阶段关系缺口 | 图示 308 条应有关系、301 条已验证、7 条缺口；“应有”来自已登记业务事实，不来自已观察到的边 | B/N：Q1 的 `expected_count/verified_count/missing_count`。点击缺口筛选交接矩阵。待核验/缺失不能算通过。 |
| O3 审计结论待复核 | 完成的审计任务不等于人工已复核；图示 86 份完成、3 份待复核 | B/N：审计结果与复核投影。打开下方待复核队列，不跳测试评估任务列表。 |
| O4 当前范围说明 | 解释统计包含哪些交接阶段，排除不适用场景 | B：审计策略的阶段定义；F：文字呈现。策略未提供时不猜分母。 |
| O5 证据交接矩阵 | 数据→治理、治理→训练、训练→模型、模型→调用、输出→场景五类关系的完整度 | B/N：Q1；点击过滤进入谱系、推理或整链。只有本行来源的缺口清单，不能随意选默认任务。 |
| O6 待复核队列 | 进入需要人工检查的审计产物 | B/N：Q3 分页，按 `review_status=pending`；每行携带确切审计任务、模型版本和对象引用。 |

|---|---|---|

### 4.4 推理路径审计

| 组件 | 意义 | 来源与交互 |
|---|---|---|
| R1 调用/模型版本与重新审计 | 查询历史结果；“重新审计”才新建任务 | B：Q5 解析调用记录及真实任务 ID，再 Q3；执行沿用 `reasoning_audit`。选择变化先清空旧结果。 |
| R2 步骤路径 | 输入、输入检测、模型调用、输出检测、治理输出的时间与证据 | B：`reasoning_audit.steps/risk_nodes/audit_result`、任务日志；只有实际记录的可观测步骤，不等同于内部隐藏思维链。 |
| R3 风险步骤证据 | 显示命中规则、原输出和治理后输出证据、复核状态 | B：上游语义风险结果与审计结果。查看脱敏片段在本模块抽屉，未经授权不显示全文；事件按钮跳风险页。 |

### 4.6 风险预警

| 组件 | 意义 | 来源与交互 |
|---|---|---|
| A1 筛选与分页 | 等级、状态、阶段在服务端过滤，示例12条仅展示5条 | F筛选，B分页总数；Q6。不得在一页数据上计算全局数量。 |
| A2 事件队列 | 统一查看跨阶段风险，选择一行查详情 | B：`alerts` 加对象引用。队列只列告警摘要，不重复数据样本、聊天记录或训练任务大表。 |
| A3 事件证据与历史 | 风险依据、影响对象、责任人、追加的处置记录 | B/N：Q6 详情与 `alert_events`。事件状态由最新有效事件投影，保留原告警事实。 |
| A4 认领、查看证据/链路、复核 | 完成“认领→补证→复核→关闭”闭环 | 写操作由后端权限、状态机、证据核验控制。提交前显示确认内容；失败不更新为已处理。状态图 `alert-review-state.png` 展示补证为空时禁止提交。 |

### 4.7 全链路与共享抽屉

| 组件 | 意义 | 来源与交互 |
|---|---|---|
| F1 Trace/调用查询 | 解析本次调用与历史来源；同名 ID 不跨实体猜测 | B/N：Q5；以已解析 task_id 或 dataset_id 调用 `full_chain_audit`，不能把不支持的 trace_id 直接塞入规范必需 input。 |
| F2 五要素 | 对全部适用阶段分别检查输入、时间、接口、版本、输出 | B/N：Q4 或 `full_chain_audit` 扩展 `checks`。任一必需项缺失整链不能通过；未知/不可用不能显示齐全。 |
| F3 八阶段表 | 原始数据、清洗、训练版本、训练、模型、推理、输出、场景；区分历史来源/本次调用 | B：谱系 + 本次日志 + 结果引用；N：`record_scope`、`source_trace_id`。看源记录在本地抽屉，精确跳转仅用于已支持的页面。 |
| F4 整链结论 | 汇总缺口原因与复核结论，并定位 ALT-2309 | B：审计服务，不由前端根据颜色或固定文案推断。审计任务执行成功也可能证据不完整。 |
| S1 源证据抽屉 | 不修改原页面也能精确查看单条来源记录 | B/N：Q7。仅含审计需要的对象、版本、时间、证据字段和来源引用；复制完整 ID/进入原模块供后续操作。 |

## 5. 与其他页面的实际串联方式

| 方向 | 当前代码支持情况 | 本次实施行为 |
|---|---|---|
| 模型训练 → 训练监控 | 已传 `trainingTaskId` | 合规页接收、校验、加载；未知 ID 显示未找到，不能选第一条。 |
| 模型调用 → 全链路 | 已传 `taskId`（实际上可能是调用记录 ID）、`traceId` | 调用解析接口得到规范实体；两者指向不同对象时提示关联冲突，不擅自选一个。 |
| 模型评估 → 神经元审计 | 已传 `modelId` | 加载模型版本和可用捕获记录；无法唯一定位时请用户选择，不能随机显示矩阵。 |
| 合规 → 模型管理 | 页面读取 `modelId` | 可以按实际 `modelId` 定位模型；页面不能定位具体历史版本时在抽屉保留版本信息。 |
| 合规 → 模型调用/评估 | 页面读取部分 `modelId`/`serviceId` | 仅称“打开该模型工作台”，不声称定位历史调用或指定评测记录。 |
| 合规 → 数据集、治理任务、训练任务、场景/测试记录 | 原页面尚无通用精确定位 | 先在 S1 抽屉展示精确来源证据，提供“复制 ID”和“打开来源模块”。不为此改其他页面，不声称源页面已自动定位。 |
| 合规 → 测试评估 | 证据引用由后端 `test_records.evidence` 关联 | 只读展示关联 test_no，或打开测试评估模块；不自动创建测试、不复制指标。 |

新增“审计总览”仅为合规模块的本地第一个 Tab，对应 `/compliance`；其余六个路径保持不变。全局导航、搜索和其他模块 Tab 不增加新条目。

## 6. 后端接口与缺口清单

### 6.1 已有契约，不等于已部署

- 项目已有前端调用封装：`POST /api/v1/tasks/execute`，`GET /api/v1/tasks`，通用 `GET /api/v1/{resource}`。
- 规范已有资源和能力：`GET /tasks/{task_id}`、异步 `POST /tasks`，`/datasets`、`/models`、`/alerts`、`/logs`、`/test-records`、`/scenarios`。具体字段和过滤支持须后端核对。
- 规范能力输入：`lineage_audit` 接受 model_id/dataset_id/task_id 至少一个；`training_monitor` 必须 training_task_id；`reasoning_audit` 用 inference_id，或 model_id+input；`neuron_audit` 必須 model_id，layer 可选；`full_chain_audit` 用 task_id 或 dataset_id。不修改这些能力码或基础输入含义。

优先 GET 已落库结果。普通页签切换、筛选、刷新不发执行 POST。只有用户触发“重新审计”才创建任务，并显示 pending/running/succeeded/failed/cancelled。`succeeded` 表示审计执行成功，不表示合规通过。

### 6.2 建议新增查询契约（Q1–Q7）

以下为本次设计提出的接口，压缩包未包含对应后端实现。它们只聚合已有事实，不在 GET 中重新运行算法或创建告警。

| 编号 / 端点（均在 `/api/v1` 下） | 参数 | 最小返回字段与页面 |
|---|---|---|
| Q1 `GET /compliance/overview` | `from,to,scope` | `as_of,scope,handoffs[{kind,expected_count,verified_count,missing_count,unavailable_count}],pending_reviews_count,completed_audits_count`；O1–O5。 |
| Q2 `GET /compliance/lineage` | `entity_type,entity_id,version_id,direction` | `nodes[{id,type,entity_id,version_id,label}],edges[{id,from_id,to_id,relation,verification_state,evidence_refs}],gaps`；L1–L4。支持多父节点，不受单个 prev_id 限制。 |
| Q3 `GET /compliance/audits` | `capability_code,subject_type,subject_id,version_id,review_status,page,page_size` | 分页审计摘要；`GET /compliance/audits/{audit_id}` 返回 `task_id,subject_ref,result,adapter_version,data_origin,review_status,evidence_refs`；O6、T/R/N。 |
| Q4 `GET /compliance/traces/{trace_id}` | 可选 `include_provenance=true` | `current_trace_id,records[{stage,record_scope,subject_ref,source_trace_id,occurred_at,evidence_refs}],checks[],gaps[],audit_ref`；F1–F4。历史来源关系只读关联。 |

需要使用已有项目真实的模型/数据/训练选项接口，或让 Q5 提供引用候选；不能额外假定所有资源详情端点已实现。所有列表分页与规范一致。数据版本可能是数字 dataset_id，模型工作台 ID 是字符串；本模块内部使用带实体种类的引用，不在全局强制改 ID 类型。

### 6.3 告警动作与审计复核

| 动作 | 请求体（JSON snake_case） | 服务端约束 |
|---|---|---|
| `POST /alerts/{id}/claim` | `expected_version` | 身份取认证上下文，pending→processing；并发认领冲突返回409。 |
| `POST /alerts/{id}/evidence` | `evidence_refs[],reason,expected_version` | 追加补证引用，不覆盖原证据；检查证据归属、权限与存在性。 |
| `POST /alerts/{id}/resolve` | `review_conclusion,evidence_refs[],expected_version` | 仅processing可申请关闭；必需证据和规则复核通过才resolved；结论由服务端记录操作人、时间。 |
| `POST /compliance/audits/{id}/reviews` | `conclusion: confirmed|rejected|needs_evidence,reason,evidence_refs[],expected_version` | 新增人工复核记录；与任务运行状态、合规结论分开，绝不改原算法结果。 |

本期使用 `pending→processing→resolved`，不随意新增与规范冲突的告警枚举。告警与日志历史按规范追加留痕；新增 `alert_events` / `audit_reviews` 或等价事件存储，当前状态通过投影获得。写操作持久化、权限、幂等、事务与并发检查属于平台真实机制，不能以浏览器数组修改代替后端成功。

### 6.4 结果字段补充与前后端分工

- `subject_ref`：至少含 `entity_type`、完整 `entity_id`、`version_id`/`model_version`；`evidence_refs` 存稳定引用。UI 短别名不用于接口。
- `verification_state`：新增证据状态 `verified/missing/unavailable/not_applicable`；与既有 `compliance_status: normal/risk/alarm` 分字段。前端不能把 unknown、unavailable 或无权限映射为 normal。
- 五要素 `checks[{key,required,state,evidence_refs,missing_reason}]`：每个适用阶段均需核验；不适用必须有策略说明；分母为零显示“暂无可核验对象”。
- 训练结果补 `checks` 和检查点证据；神经元结果补 `model_version,inference_id,capture_id,layer_indices,neuron_indices,unit,normalization_baseline,threshold,heatmap,abnormal_neurons,observed_count`。这些是新增结果契约，需适配器支持。
- 若新建神经元审计必须锁定版本/捕获，规范 input 原本不足，需将该能力的版本/捕获扩展契约写进服务端 schema 并完成联调；不得未经确认就增加必填字段破坏旧调用。仅按 model_id 得到的泛化结果不能绑定到某次推理。
- 业务对象、版本、时间、计数、风险/合规结论、五要素、规则、证据、图边与热力图全部来自**后端**。前端只做筛选状态、格式化、图布局、缩放、选中/展开与路由导航。
- 统一响应 `{code,message,data,trace_id,timestamp}`；请求响应追踪 ID 与被审计业务 `trace_id` 概念分开，查询对象必须显式在参数中传递，不能用全局 lastTraceId 代替。
- 源记录包含敏感内容时后端返回脱敏字段，列表不暴露原文；403 是无权限，404 是找不到，409 是状态/版本冲突，502/超时是不可用。错误不得替换成成功示例。

## 7. 状态与验收

每页都应有加载、未选择对象、无结果、失败重试、无权限、部分证据缺失状态；神经元页另有“不支持内部捕获”；异步结果需防止旧请求覆盖新选择。变更筛选会重置分页。离开页面停止轮询，轮询 GET 不能重复创建执行任务。

图中示例口径已统一：关系总数128+52+18+86+24=308；缺口0+1+0+3+3=7；谱系4条关系中3条核验、1条待补证；训练4项检查中3项通过、1项缺失；激活矩阵192个单元3项异常，3/192=1.56%；风险队列只展示pending/processing；整链列出8阶段且包含同一个CP-12缺口。

验收应覆盖：7条页面地址不同内容；三个现有入站链接正确解析对象；只读来源抽屉精确取数；无历史结果不自动调用算法；告警并发认领/补证不足不能关闭；真实接口失败不混入Mock；不可用激活不生成图；完整关联不等同于安全无风险；其他页面文件无改动且共享布局在非合规路径输出保持一致。

本次交付是设计图、报告和实施指令，未实施或声称完成前后端联调。后续 Codex 应按这些边界编写可运行界面与真实请求层，并明确汇报服务端实现状态。
